## 立即可走查的流程

构建与安装包路径见[原型说明](../prototype/README.md)。本原型使用调试签名，包名`local.dshx.prototype`，不替换其他应用。首次使用不要求无障碍或真实模型密钥。

1. 工作台 → 用周会样本开始 → 查看范围与接收方演练 → 固定本地规则整理 → 对照原文行号 → 另存为新文件。原文件保留；实际结果应匹配固定预期。
2. 文件结果 → 撤销这次整理。若副本后来被修改，不覆盖后来的编辑，而是创建恢复副本。本包用例可注入该冲突，原型未提供通用编辑器。
3. 手机任务 → 开始演练 → 提交前确认。拒绝/过期后结束；离开任务页后通过固定任务条直接停止。此过程没有真实目标应用或动作。
4. 演练允许后停止 → 显示“停止中” → 演练丢回执 → “结果不明” → 补充人工核实记录。原动作仍为结果不明，没有重试入口；新开演练与重发旧动作分开。
5. 设置 → 进阶与恢复演练 → 完全信任演练 → 退出 → 查看重建与保留项 → 恢复失败演练 → 从保留文件进入导出。演练不清除真实文件，也不执行恢复脚本。

本轮文件上限 256 KiB、文件名 120 字符、审批演练 30 秒是原型参数；正式版限额仍须基于产物与真机确定。20 次模型请求 / 10 分钟仍是既定待验证默认值，原型不执行或消耗真实模型额度。整个流程的实际模型调用为“未发生”；正式版未知用量不能显示为零费用。

## 样本、环境与证据工具

[cases.json](cases.json)由项目组维护 T1–T3 的固定任务实物和状态；每次修改样本必须同步哈希并登记版本，不能在测试失败后静默改目标。T2/T3 缺项保留为空，不预填假应用、假插件或假报告。

`tools/p0.py` 是开发机只读准备工具，由维护者主动调用。它校验固定文件、收集构建环境或指定设备的系统信息，不安装应用、不获取页面/账号、不执行动作、不请求模型，也不自动通过任何 Gate。设备标识在记录中只存 SHA-256；新证据必须用新文件名，不覆盖旧记录。

```bash
python3 tools/p0.py check
python3 tools/p0.py inventory --output .analysis-tmp/p0/host-unique.json
python3 tools/p0.py collect --serial 已授权设备编号 --output .analysis-tmp/p0/device-unique.json
```

`check`返回 0 只表示固定样本完整性没有出错，仍会显示未补齐实物和“Gate 未通过”；设备信息采集不证明 Node/PTY、16KB、TLS、审批或恢复可用。没有设备时明确拒绝，不生成空的通过记录。

用户走查使用[STUDY.md](STUDY.md)，由实际参与者完成后填写，当前没有任何参与者或结果。模型服务密钥和用户资料不得写入样本、日志或研究模板。

独立只读复查发现的两项边界已修复：初始化期间返回的导入请求会等待本地准备完成，冲突恢复时过长的文件名保留扩展名并截短中段。两个复现用例均先在旧实现失败，再验证修复结果；它们属于本包故障覆盖，不代表真实进程回收或存储提供方的设备验证。
