# G0 用户走查脚本与记录模板

当前状态：未招募、未执行；此文件不是用户证据。G0 指项目组在正式开发前组织的产品走查，由真实目标用户操作可运行原型，区别于自动化测试与作者自己检查。通过标准只以 本地实施计划（仅本地保留） 为准。

先固定 APK 的 SHA-256、[任务清单](cases.json)、原型版本、设备与日期，再邀请至少五名已有 dsh/模型配置经验、愿意参与的目标用户。使用编号 U01–U05；不要收集真实密钥、客户资料或账号密码。屏幕录制或访谈内容须参与者自愿同意，默认只记本地脱敏操作记录。

主持人只给目标，不指出按钮位置；参与者请求帮助时先记录卡点，代操作的任务不能记为独立成功。真实目标 App 与审核插件尚未固定，相关部分只可记为演练理解验证，不能伪装成任务兼容或 G0 整体通过。

1. “用这份周会样本得到可交付的未完成事项列表，确认没有丢掉内容，并保存为新文件。”记录是否找到原文、结果、撤销和另存为；让参与者在另一个应用打开结果。失败保留文件并记录原因，不用模型成功文案代替文件证据。
2. “假设刚才整理要使用你配置的模型。你认为会发送什么、发给谁？切换到另一个服务后还能直接发送上次的内容吗？”记录参与者自己的表述，不先解释答案。这里不发送真实数据。
3. “走查一次手机任务，在提交前决定是否允许，然后离开任务页并停止它。”观察固定任务条的直接停止入口能否被独立发现。
4. “再走查一次，动作已经发出，但系统没有返回结果。你会如何继续？停止是否意味着提交没有发生？”记录是否选择先核实、是否误以为可以直接重试；说明演练没有真实目标应用，不能要求真实核实证据。
5. “完全信任模式退出后恢复失败。请找到保留的成果，并说明哪些内容将重建、哪些保留。”检查是否误以为要删除整个应用数据或从头配置所有内容。
