# 离线运行包安装与完整性检查

[说明索引](README.md) · [术语与架构](architecture.md) · [返回项目](../README.md)

运行包是随 Android 安装包提供的程序与依赖集合，由构建脚本生成、引擎安装组件校验；它与用户数据分开。

本文所称 **Android 宿主**是 `app/` 中由系统创建的 Kotlin 应用，负责页面与系统交接；**dsh** 是宿主启动的官方智能体引擎，负责会话、模型请求和工具调度；**Node** 是执行 dsh 与适配模块的 JavaScript 运行程序。其他通用概念见[术语表](architecture.md#术语与整体架构)。

**会话**由 dsh 创建并分配稳定编号，保存一段对话与工具事件；**工具**由引擎或插件注册，是模型可以提出调用的命名操作，执行结果由程序返回。

## 职责与实现

**作用。** [`CoreStore.kt`](../app/src/main/java/local/dshx/app/CoreStore.kt) 由 `Engine` 创建，负责把 APK 内的运行资源安装到应用私有目录。这里“离线”指安装运行环境无需临时下载 Node 或 dsh；不表示云端模型调用无需联网。

运行包内预装 Git；`bin/git` 是主程序，`libexec/git-core` 保存它调用的传输助手和子命令入口，`share/git-core/templates` 保存新建仓库模板。相关文件与 Node 一样由固定版本和摘要锁定，随 APK 安装，无需用户另装 Termux 或 Git。HTTP/HTTPS 传输的依赖库和证书也包含在运行包中。

运行包也提供可直接输入的 `npm` 和 `pnpm` 命令。两个入口由构建脚本生成，使用 Android 的 `/system/bin/sh` 启动同一运行包的 Node，并把参数和退出码交给对应的包管理程序；入口随清单登记执行权限，缺失时触发安装修复。执行包内脚本默认使用预装 Bash，可通过 `npm_config_script_shell` 显式指定其他 shell。用户安装的依赖应保存在用户目录或工作区，避免修改经过校验的运行包目录。命令可用不代表下载的包支持 Android；需要原生扩展或额外系统程序的包仍需单独适配。应用内插件安装继续使用原有入口及兼容性检查。

## 预装命令环境

[`tools/runtime.py`](../tools/runtime.py) 由运行包构建入口调用，安装下表中的 Android 程序、Python 标准库及命令入口。所有软件包及传递依赖均在 [`termux.lock.json`](../core/termux.lock.json) 中锁定版本、下载地址和摘要；构建只提取文件，不运行软件包安装脚本。

| 环境 | 可直接使用的命令与用途 |
|---|---|
| JavaScript | `node`、`npm`、`pnpm`、`npx`、`pnpx`；运行脚本、管理包、执行包提供的命令 |
| SSH 客户端 | `ssh`、`scp`、`sftp`、`ssh-keygen`、`ssh-keyscan`、`ssh-agent`、`ssh-add`；远程命令、文件传输及密钥管理 |
| 网络与结构化数据 | `curl` 发起网络请求，`jq` 处理 JSON，`sqlite3` 读写 SQLite 数据库 |
| Python | `python`、`python3`、版本化入口及 `pip`、`pip3`；包含标准库、常用原生标准模块与离线创建虚拟环境需要的 pip wheel |
| 文件与文本 | GNU coreutils 的基础命令，findutils 的 `find`、`xargs`，diffutils 的 `diff`、`diff3`、`cmp`、`sdiff`，以及 `patch` |
| 归档与压缩 | `tar`、`gzip`、`gunzip`、`zcat`、`zip`、`unzip`、`zipinfo` |
| 同步 | `rsync`，支持本地同步及通过 SSH 连接装有 rsync 的远端 |

**Android 路径适配。** `termux-exec` 是随包分发的官方兼容库，由宿主通过 `LD_PRELOAD` 加载，负责把脚本常见的 `/usr/bin/env`、`/bin/sh` 等执行入口解析到当前运行包。`LD_PRELOAD` 是告诉系统加载器提前加载指定共享库的环境变量；这里不提供完整 Linux 文件系统。宿主同时配置应用目录和运行包目录，禁用该库的系统链接器执行模式，保留项目现有 Android 目标版本的进程启动方式。运行包版本目录使用较短名称，以满足该兼容库的目录长度限制。

GNU coreutils 的多个命令共用一个主程序，构建生成小入口，避免为每个命令重复打包主程序。`tar` 等程序写死的 Termux shell 路径在构建时改为 Android shell。`stdbuf` 的辅助库保存在主程序旁，便于程序按自身位置查找。

**SSH 用户文件。** 默认配置包含 `$HOME/.ssh/config`，默认密钥和已知主机记录也位于 `$HOME/.ssh`；命令行选项仍优先。创建密钥的常见选项未提供 `-f` 时，入口补入 `$HOME/.ssh/id_<类型>`；查看、转换等其他密钥操作按 OpenSSH 原命令参数执行，建议明确传入文件路径。`scp`、`sftp` 和 rsync 默认调用当前运行包的 SSH；rsync 允许通过 `RSYNC_RSH` 指定其他连接命令。ssh-agent 的默认通信文件放在宿主提供的临时目录中。运行包不提供常驻 SSH 服务。

**Python 用户环境。** Python 从同一运行包查找标准库；宿主把字节码缓存写入 `$HOME/.cache/python`，避免向校验过的运行包增加文件。推荐在工作区创建独立虚拟环境：它是用户创建、拥有独立安装目录的 Python 环境，安装包不会写入公共运行包。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install 包名
```

Python 标准库与 pip 可离线启动，虚拟环境的 pip 初始化使用包内 wheel；下载第三方包仍需要网络，带原生扩展的第三方包可能需要额外适配与编译工具。基础运行包没有附带完整编译工具链。

## 内置软件装配技能

安装包预置 [`install-dshx-software`](../app/src/main/assets/skills/install-dshx-software/SKILL.md)，用于让 dsh 安装、升级和验证新的环境、命令行程序或本地应用。技能是提供给智能体的操作指令与参考资料，由宿主启动时复制到 `$HOME/.dsh/skills/install-dshx-software`，再由引擎的技能发现机制读取；它不会自行运行安装任务。用户编辑过的技能文件会保留。

用户可以提出“安装一个处理 PDF 的 Python 工具，并验证它能读取文件”“为这个 Node 项目安装依赖并启动本机服务”等请求。技能要求先检查现有环境和 Android 兼容性，将新增软件放入用户目录或项目目录，提供实际入口、独立环境、安装记录及核心功能验证；微应用、插件和独立 Android 应用使用各自真实可用的安装入口。

当前终端不会自动加载 `.bashrc` 或 `.profile`，因此技能明确要求提供绝对路径或显式加载环境文件，并验证新终端中的调用方式。它不通过修改已校验运行包来实现安装，也不把临时 PATH 生效当作跨会话装配完成。

## 运行包结构与校验

运行包分为三个文件：

| 资源 | 谁生成、保存什么、谁使用 |
|---|---|
| `core.zip` | `tools/core.py` 生成的运行文件压缩包，由 `CoreStore` 解包 |
| `core.json` | 同一构建生成的机器校验清单，包含架构、版本、压缩包大小与 SHA-256、逐文件大小与执行位；SHA-256 是用于核对内容是否相同的摘要值 |
| `core-info.json` | 同一构建生成的摘要信息，供管理页显示并辅助 Gradle 选择架构；不代替完整安装校验 |

**安装原理。** 安装器先检查空间，把压缩包复制到暂存位置并核对整体摘要，再逐文件解压、核对内容摘要、大小和路径。全部成功后写 `.verified` 安装收据，并将暂存目录改名为正式版本目录。重复路径、越界路径、未登记文件、缺失文件和取消都会阻止激活。

**快速启动与修复的区别。** 解析清单时一次性记录全部可执行文件；`installed()` 检查收据、固定启动文件和这些可执行文件的存在、大小、执行位，新增命令无需再逐个登记快速检查列表。`current()` 遍历整个版本目录，检查所有文件摘要及额外内容；`install()` 先尝试完整复用，不合格时重新安装。普通启动不重复扫描全部依赖或计算文件摘要，以减少冷启动开销。因此快速检查不保证识别任意同大小内容变更，也不构成同一应用身份内恶意代码之间的隔离。

运行目录使用 `<版本>-<压缩包摘要前16位>`，同一上游版本的不同构建互不覆盖。旧版本不会自动回收，也没有通用一键回退入口；运行包升级不应覆盖用户目录。
