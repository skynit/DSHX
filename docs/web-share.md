# 网页共享

端点用户可将已经运行的 HTTP 或 HTTPS 服务登记给 DSHX。**共享条目**是发布者在手机上保存的名称、固定地址和启用状态，不是网页文件，也不授予访客其他设备权限。

## 使用

1. 在「设置 → 聊天设置」启用端点并关闭隐身，保持引擎后台服务在线。暂停新聊天不影响网页共享。
2. 在「设置 → 网页共享」添加服务。填写 `http://127.0.0.1:8080/` 可共享手机本机服务；填写 `http://192.168.1.20:8080/` 可代转当前 Wi‑Fi 或有线局域网内的固定 IPv4 地址。也可填写 HTTPS；目标证书必须能用其登记地址正常验证。DSHX 不启动或保活目标服务，也不共享引擎和手机管理端口。
3. 条目默认停用。显式开启后，**端点公开时任何访客都可以访问该服务的页面和接口**。填写的路径仅是首页，不是访问权限。不要把仅靠局域网隔离、没有自己的认证的管理后台启用为共享。
4. 访客可用浏览器访问平台 `/web/`，或打开发布者复制的链接。Android 用户也可在「聊天 → 发现 → 查看网页」打开浏览器标签页。本版 Android 使用同一个 Web 访问运行时，不另起本机代理端口。访客无需 DSHX 登录；应用自身的登录不受替代。
5. 关闭访问标签页会释放连接；设为隐身、停用、移除或编辑共享会终止相关连接和请求。换网络或重启 DSHX 后，局域网条目需要在编辑页重新保存确认。网页服务本身离线时，中继无法让它恢复。

也可以在 dsh 的本机聊天里说「做一个可共享的活动公告页」，或输入 `/create-dshx-web-share 登记 http://127.0.0.1:8080/`。内置技能可以创建并运行网页服务，也可以登记已经运行的服务。它只保存停用条目；检查后在「设置 → 网页共享」手动启用。用 dsh 终端运行的服务会受应用和系统进程生命周期影响，不会开机自启。

## 平台部署

用 `python3 tools/tunnel.py build` 构建穿透平台包。与 [聊天平台](tunnel-chat.md) 同一个进程，可选配置：

| 配置 | 用途 |
|---|---|
| `DSHX_WEB_ORIGIN` | 可信访问页和信令来源，例如 `https://tunnel.example.org:8443`；应与 Android 中配置的平台地址相同。 |
| `DSHX_WEB_APP_DOMAIN` | 独立应用域名，例如 `dshx-apps.example.net`。为 `*.dshx-apps.example.net` 配置 DNS、泛域名证书和 HTTPS 反向代理，端口与可信来源一致。 |
| `DSHX_WEB_VISITOR_IP_HEADER` | 可选，例如 `x-real-ip`。只有平台入口受可信反代保护、反代始终用访客的真实 IP 覆盖该头时才能设置；否则按直连平台的 IP 计数。 |

前两个配置必须同时提供。反向代理保留外部 `Host`，转发可信来源的 `/web/`、`/api/v1/dshx/web/signaling`（WebSocket 升级）、既有聊天目录和信令路径，以及应用泛域名的 `/__dshx/`。其他应用子域名路径不得交给平台 HTTP 代理。浏览器的 Service Worker（拦截应用网页请求的后台脚本）接管业务路径；没接管时平台明确返回 `404`。

中继复用[聊天的 TURN 部署配置](tunnel-chat.md)：配置 `DSHX_TUNNEL_TURN_URLS` 和 `DSHX_TUNNEL_TURN_SECRET_FILE`，并保持 coturn 的私网目的地址限制、带宽和连接配额。未配置 TURN 时网页只尝试直连。已有部署须同时更新 Android 发布端和平台；浏览器代码由平台提供。

## 连接与兼容边界

- 平台用公开端点目录寻址，并为来自可信 HTTPS 页面的 WebSocket 连接分配短期访客身份。游客不进入目录，也不能发起聊天。发布者用端点密钥签署本次会话的连接协商内容，浏览器核对签名和可信端点编号后才发送网页请求。
- 平台会回收长期未建立连接的访客；访客连接最长 30 分钟，同一来源最多同时占用 16 个访客信令连接。连接到期后需重新打开应用。
- 业务用独立的 `dshx-web/1` WebRTC 数据通道。先用本机地址和 STUN（协助发现可直连地址的服务器）尝试直连；平台已配置 TURN 时，直连失败或约 12 秒仍未建立，浏览器才申请一次只走中继的新连接。TURN 只转发双方加密的数据，平台的信令服务只负责交换建连信息，不接收网页内容。双方核实实际选中的路径后才放行，浏览器显示「已直连」或「已通过中继连接」。已发出的业务请求不参与回退。
- 平台只向已结束一次直连尝试、目标仍在线公开的访客签发中继凭据。每条访客连接最多签发一次，凭据最长有效 30 分钟；同一来源在该有效期内最多签发 32 组。信令许可只用于指定端点和新连接，不向访客下发服务器共享密钥。
- 网页、登录 Cookie（应用用来识别登录状态的数据）、上传下载和实时流量限制在本次访问、固定目标内。Android 侧 Cookie 保存在内存中，不会交给其他访客或发送到平台，页面依赖直接读取服务端 Cookie 时需单独验证。流量有大小、并发和超时保护；上传单次上限 128 MiB，当前 WebSocket 单消息上限 12 KiB。连接断开后不自动重放写入。
- 不支持依赖自带 Service Worker 的应用。WebSocket 适配覆盖普通 HTML 页面中的同站连接；页面安全策略禁止该脚本或禁止嵌入时不会绕过。依赖原域名、外部认证跳转、固定回调、特殊多窗口行为的站点需单独验证。代理把请求中已有的 `Origin` 改成 `https://dshx-web.invalid`，用于标记来访请求，不伪装成同源。站点如需允许该来源，应保留自己的身份验证和权限检查。

## 定向验证

- Android：`./gradlew :app:testDebugUnitTest --tests 'local.dshx.app.CoreTest.webShare*'`。
- 平台：`node --test core/tunnel-platform.test.mjs`。配置 `DSHX_PLAYWRIGHT_MODULE` 为 Playwright 的 ESM 入口、`DSHX_CHROME_PATH` 为 Chrome 路径可启用实浏览器用例。另配置测试专用 `DSHX_TEST_WEB_TURN_URL` 和 `DSHX_TEST_WEB_TURN_SECRET` 可阻断测试端直连，验证确实通过 TURN 加载、上传和下载；此用例以浏览器代替 Android 发布端。
- 部署后应分别验证浏览器和 Android 浏览器标签页能打开手机本机、局域网各一个服务；再检查发布端隐身、网络切换、确实无法直连时的界面结果。构建或上述定向测试不能代替真机验收。
