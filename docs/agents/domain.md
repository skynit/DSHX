# 领域文档

本仓库采用 single-context 布局：
项目术语统一记录在根目录 `GLOSSARY.md`，
架构决策记录统一放在 `docs/adr/`。

术语表解释项目概念及其准确名称。
架构决策记录（ADR，Architecture Decision Record）说明一项设计选择、
选择理由及影响，供后续方案核对和追溯。

## 探索代码前读取

- 若根目录存在 `GLOSSARY.md`，读取其中与当前任务有关的术语。
- 若存在 `docs/adr/`，读取影响当前工作范围的决策记录。
- 若以后出现根目录 `GLOSSARY-MAP.md`，它表示多个领域的文档入口；
  按映射读取相关术语表，并检查对应领域目录内的架构决策记录。

文件尚不存在时直接继续，不因缺少文件阻塞任务，
也不为填充目录提前创建空文档。
由 `domain-modeling` 技能在实际确定术语或决策时按需创建。

## 统一用词

需求标题、规格、设计说明、测试名称等涉及项目概念时，
沿用术语表中的名称和定义，避免使用术语表已明确排除的同义词。

遇到尚未定义的概念，先核对代码和已有文档中的实际用法。
确有术语缺口时，将其交给 `domain-modeling` 处理。

## 处理决策冲突

方案与已有架构决策冲突时，明确指出对应记录、
冲突内容，以及建议重新评估的依据，交由用户决定是否调整。
