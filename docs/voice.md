# 语音输入、在线播报与模型分工

[说明索引](README.md) · [术语与架构](architecture.md) · [返回项目](../README.md)

当前主开发分支默认使用 Edge TTS 在线播报，也可配置火山引擎。语音识别与声音唤醒继续在手机上运行；播报不需要下载模型。旧的系统离线播报、MeloTTS、ZipVoice 声音克隆、参考录音管理及降噪方案已移至 `codex/local-voice-archive` 分支，保存提交为 `9780c76`。该分支同时保存切换方案前的全部未提交工作与本地语音诊断说明。

## 名称与分工

| 名称 | 是什么、由谁配置、负责什么 |
|---|---|
| Android 宿主 | `app/` 内的原生应用，由 Android 创建，负责界面、权限、麦克风、播放与服务配置。 |
| dsh | 随应用提供、由宿主启动的 DeepSeek 智能体引擎，负责聊天模型请求、工具与持久对话历史；它不负责在线语音合成。 |
| 语音识别 | 把麦克风录音转换为文字。宿主用用户下载的 SenseVoice 模型在手机完成，与将文字读出声音的播报相反。 |
| 声音唤醒 | 宿主使用随应用准备的关键词模型检测用户配置的短语，只负责启动收音，不代替完整语音识别。 |
| TTS | Text to Speech，即把文字生成声音。由宿主把回答文字发送给用户选定的 Edge TTS 或火山引擎，服务返回音频后在手机播放。 |
| Edge TTS | 微软 Edge 朗读服务，本应用默认使用，无需用户填写密钥，仍然需要联网；不是可下载的离线模型。 |
| 火山引擎 | 用户自行开通的在线语音服务。用户在语音控制台创建凭据、开通音色，在本应用填写相应配置；不会借用聊天模型服务的密钥。 |
| API Key | 火山语音控制台创建的接口密钥，应用放入请求头 `X-Api-Key`；与旧版的一对 App ID、Access Token 是两种独立的鉴权方式。 |
| 资源标识 | 火山控制台用于标明开通语音资源的名称，默认 `seed-tts-2.0`；与指定声音的音色编号不同，也不是模型下载地址。 |
| 模型分工 | 用户单独配置的短文本或截图理解模型，负责生成回答；它与只负责朗读回答的播报服务分别设置。 |

## 使用入口

1. 打开“设置 → 语音 → 语音播报”。新安装及由旧版覆盖升级后，没有保存在线播报配置时默认选中 Edge TTS，音色为 `zh-CN-XiaoxiaoNeural`（晓晓）。不要求下载播报或克隆模型。
2. 可直接选择“试听音色”。常用音色提供晓晓、云希、曉臻，也可填写服务支持的完整音色编号。修改服务或音色后，先点“保存播报设置”，再试听。
3. 使用火山引擎时，选择“火山引擎”，按控制台提供的凭据选择“API Key”或“App ID 与 Access Token”，填入对应字段。默认使用语音合成 2.0，音色为“小何”`zh_female_xiaohe_uranus_bigtts`，资源为 `seed-tts-2.0`。它与 1.0 的“湾湾小何”`zh_female_wanwanxiaohe_moon_bigtts` 是不同音色；已有明确保存的资源和音色不会被新默认值覆盖。实际可用性取决于密钥所属项目是否开通对应资源与音色，声音复刻服务单独开通不代表拥有语音合成权限。
4. 开始语音对话前，仍需在模型资源区下载约 229 MiB 的语音识别模型，启动 dsh 并配置聊天模型。在底栏选择“语音”，识别文字会进入当前 dsh 会话，正式回答自动交给已保存的播报服务朗读。试听不要求启动 dsh，也不要求下载识别模型。
5. 多轮语音页立即显示识别文字，回答返回后补入对应消息。结束语音或切换到文字对话会停止录音、在线合成请求与播放。失败时保留已经得到的文字回答，并显示可操作的错误提示。
6. 按需设置唤醒短语和后台声音唤醒；简单任务与截图理解继续在“设置 → 模型分工”配置。

录音仅用于本机识别；识别文字可能发送至聊天模型，助手回答文字会发送至所选播报服务。模型下载镜像只改变识别与文本模型的下载来源，与在线播报服务没有关系。网络或播报服务不可用时不会换回旧的本地合成方案。

## 自定义分工模型

**模型来源**由用户在原生设置中选择，决定简单语音任务交给哪个模型；**服务标识**是聊天设置为一个模型服务保存的名称，用于查找该服务的地址、协议和密钥，与服务侧实际接收的**模型名称**不同。服务地址和密钥仍由现有聊天设置管理，小模型设置只保存服务标识与模型名称。

- **默认本地**：继续使用模型资源区下载的 Qwen3 0.6B。
- **自定义本地**：点击“导入模型”选择手机上的 GGUF 文件；导入成功后自动选择该模型，也可切回默认本地。GGUF 是发布者打包模型权重与元数据的文件格式，需包含当前 llama.cpp 推理库支持的模型架构和对话模板。对话模板是发布者随模型提供的消息排版规则，负责把系统要求、多轮消息和回答起始标记转换为该模型理解的文本，不能直接用 Qwen3 格式替代所有模型。导入会检查文件头、存储空间、加载条件和模板支持，计算摘要后发布；失败或取消保留上一个模型。文件复制到应用私有目录，之后不依赖原文件的读取权限。
- **在线模型**：先在聊天设置中添加服务地址和密钥，再填写对应的服务标识及模型名称，点击“保存小模型”。保存只检查字段格式；实际服务是否可用、名称是否受支持，以模型请求结果为准。简单任务的会话上下文会发送给此服务，并按该服务规则计费。

分工开关影响规则匹配到的简单语音任务，以及任何会话中的 `phone_screenshot` 截图识别；普通文字回答和不匹配的语音任务沿用当前聊天模型。选中的模型临时用于这一轮，原模型作为后续选择保留在会话中；结束、失败或取消后恢复原选择，用户在执行期间主动改选模型时以用户选择为准。语音工作期间禁止修改来源或导入文件。

本地导入文件最大 4 GiB，仍受设备可用内存和当前推理库能力限制；扩展名正确不代表模型可运行。自定义本地模型读取自身模板，默认模型继续使用原有格式。两者保持相同的短任务上下文与输出预算，加载前的内存检查只是含余量的估算，不是系统内存预留。

**截图识别**可单独填写“截图服务标识”和“截图模型名称”，两项都留空时沿用文本分工模型。服务仍从聊天设置读取地址与密钥，不要求先下载默认文本模型。当前默认 Qwen3 与导入 GGUF 的手机推理引擎仅支持文字；需要通过已配置服务选择支持图片的模型。若服务指向用户自建的本地视觉服务，也通过同一服务配置接入；这与把 GGUF 文件导入手机运行不同。截图分工的能力检查、结果与坐标有效期见[手机能力](phone.md)。

## 请求与播放流程

`VoiceControl` 是由应用对象创建并长期持有的语音协调对象，管理收音、会话、试听、下载与取消。每次语音任务创建 `VoiceOutput` 播报对象；它读取一份已保存配置，并在本次任务内固定使用。界面不允许语音工作期间改配置，未保存草稿不能直接试听，避免界面选项与实际请求不一致。

1. 语音协调对象把识别文字通过本机通信桥交给 dsh。通信桥是宿主与引擎之间、每次启动时建立的认证连接，负责传递请求，不是外部云服务地址。dsh 复用现有会话、工具与历史，返回最终回答。
2. 播报对象清理不适合朗读的 Markdown 标记，并按标点和最多 300 个 Unicode 字符切分。Unicode 字符按完整码点计算，避免把表情符号的编码拆开。
3. Edge 通过 WebSocket 连接逐段返回 MP3。WebSocket 是应用建立的持续双向网络连接，区别于一次提交一次响应的普通 HTTP 请求。应用使用当前版本 2 请求令牌，发送语音格式与经过 XML 转义的朗读文本，解析二进制包头，收到本轮完成标记后才播放完整音频。令牌是协议生成值，与用户的云服务密钥无关。协议参考 [edge-tts](https://github.com/rany2/edge-tts)，适配实现和许可原文随本项目提供。
4. 火山通过 HTTPS 请求 `https://openspeech.bytedance.com/api/v3/tts/unidirectional`。该接口按 JSON 行陆续返回 Base64 音频片段；Base64 是把二进制表示成文字的编码方式，不是另一种音频格式。应用累积音频，遇到成功结束码 `20000000` 才允许播放；返回错误码、缺少完成标记或音频为空均视为失败。终止包可以没有音频，也可以包含最后一段音频。
5. 播放前申请 Android 音频焦点，即请求系统协调本应用与其他应用的声音。音频临时写入应用缓存，由系统 `MediaPlayer` 播放，结束或取消后释放播放器并删除临时文件。`MediaPlayer` 是 Android 的音频解码和播放对象，不在本机合成声音。
6. 用户取消、音频焦点丢失或设备变化时停止当前请求与播放。请求和播放有等待上限，单段音频限制为 8 MiB。服务报错不直接展示响应正文或凭据，文字会话继续保留。

火山请求固定传入 `user.uid`，以及 `req_params.text`、`req_params.speaker`、`audio_params.format=mp3`、`audio_params.sample_rate=24000`。所有火山请求携带资源标识与独立请求编号；API Key 模式只携带 `X-Api-Key`，旧凭据模式只携带 `X-Api-App-Id`、`X-Api-Access-Key`。不混用两种凭据，也不向重定向地址转发。

在线播报配置保存在应用私有的 `voice-output` 偏好设置中，与旧的 `voice` 设置分开。旧音色选择不会覆盖新默认值；本次升级不删除设备已有的参考录音、克隆模型或备份，因此切回归档分支仍可继续检查原方案。系统卸载与清除应用数据仍会清除这些私有数据。

## 实现文件

| 文件 | 创建方与职责 |
|---|---|
| [`VoiceControl.kt`](../app/src/main/java/local/dshx/app/VoiceControl.kt) | 应用创建的语音协调对象，维护会话、识别文字、回答、下载状态及任务取消。 |
| [`VoiceInput.kt`](../app/src/main/java/local/dshx/app/VoiceInput.kt) | 协调对象为任务创建的收音对象，在手机执行关键词检测、语音活动检测与整句识别。 |
| [`VoiceService.kt`](../app/src/main/java/local/dshx/app/VoiceService.kt) | Android 创建的麦克风前台服务，显示持续通知，并在设备变化时停止任务。 |
| [`VoiceOutput.kt`](../app/src/main/java/local/dshx/app/VoiceOutput.kt) | 协调对象创建的在线播报对象，保存及校验服务配置，处理 Edge、火山协议、音频缓存、播放与取消。 |
| [`EdgeToken.kt`](../app/src/main/java/local/dshx/app/EdgeToken.kt) | 播报对象调用的 Edge 请求令牌生成器，按协议计算版本 2 令牌，不保存账户密钥。 |
| [`VoiceModels.kt`](../app/src/main/java/local/dshx/app/VoiceModels.kt) · [`voice/models.json`](../app/src/main/assets/voice/models.json) | 识别、唤醒与可选文本模型的安装器与固定清单，检查下载大小和摘要；已没有播报、克隆或降噪模型条目。 |
| [`SmallModel.kt`](../app/src/main/java/local/dshx/app/SmallModel.kt) | 宿主创建的分工模型配置与自定义文本模型管理对象，独立于在线播报。 |
| [`voice.mjs`](../core/voice.mjs) | dsh 内的语音接入模块，提交正常用户消息并取得真实回答；保持正式会话历史与临时分工模型的恢复规则。 |
| [`LocalModel.kt`](../app/src/main/java/local/dshx/app/LocalModel.kt) · [`local.cpp`](../app/src/main/cpp/local.cpp) | 只负责可选的本机文本推理，不负责朗读。后者通过 llama.cpp 执行文本模型；llama.cpp 是构建时准备的 C/C++ 文本推理库。 |

唤醒使用 sherpa-onnx 的关键词模型，整句识别使用 SenseVoice，语音活动检测使用 Silero VAD。sherpa-onnx 是应用集成的本机语音执行库；VAD 是由收音对象创建、用来确定讲话起止的检测器，不负责识别具体文字。这部分沿用原来的下载、摘要校验与内存准入；内存准入是加载前估算，不是系统内存预留。
