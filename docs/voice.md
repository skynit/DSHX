# 语音输入、在线播报与模型分工

[说明索引](README.md) · [术语与架构](architecture.md) · [返回项目](../README.md)

当前主开发分支默认使用 Edge TTS 在线播报，也可配置火山引擎的语音合成或音频生成。语音转文字使用手机系统提供的识别服务，声音唤醒仍在手机上检测；识别与播报均不需要在应用中下载模型。系统识别是否联网取决于手机提供的服务。旧的系统离线播报、MeloTTS、ZipVoice 声音克隆、参考录音管理及降噪方案已移至 `codex/local-voice-archive` 分支，保存提交为 `9780c76`。该分支同时保存切换方案前的全部未提交工作与本地语音诊断说明。

## 名称与分工

| 名称 | 是什么、由谁配置、负责什么 |
|---|---|
| Android 宿主 | `app/` 内的原生应用，由 Android 创建，负责界面、权限、麦克风、播放与服务配置。 |
| dsh | 随应用提供、由宿主启动的 DeepSeek 智能体引擎，负责聊天模型请求、工具与持久对话历史；它不负责在线语音合成。 |
| 语音识别 | 把麦克风录音转换为文字。宿主通过 Android 的 `SpeechRecognizer` 接口调用手机已安装并启用的服务，与将文字读出声音的播报相反。Android 12 及以上且设备端服务可用时优先调用系统设备端识别，否则调用默认系统识别服务；设备端服务明确报告中文不可用或服务断开时，清理后至多回退默认服务一次。不会绑定某个品牌的包名或私有参数。 |
| 声音唤醒 | 宿主使用随应用准备的关键词模型检测用户配置的短语，只负责发现唤醒短语。检测到后先释放麦克风，再让系统识别服务收音；请在界面进入“正在听”后再说问题。 |
| TTS | Text to Speech，即把文字生成声音。由宿主把回答文字发送给用户选定的 Edge TTS 或火山引擎，服务返回音频后在手机播放。 |
| Edge TTS | 微软 Edge 朗读服务，本应用默认使用，无需用户填写密钥，仍然需要联网；不是可下载的离线模型。 |
| 火山引擎 | 用户自行开通的在线语音服务。用户在语音控制台创建凭据、开通音色，在本应用填写相应配置；不会借用聊天模型服务的密钥。 |
| 火山音频生成 | 火山独立授权的音频创作服务，应用使用 `seed-audio-1.0` 模型，给定朗读要求、文本及参考音色后接收完整音频。它与固定文本转语音的语音合成服务使用不同接口，开通其中一个不代表拥有另一个的权限。 |
| API Key | 火山语音控制台创建的接口密钥，应用放入请求头 `X-Api-Key`；与旧版的一对 App ID、Access Token 是两种独立的鉴权方式。 |
| 资源标识 | 火山控制台用于标明开通语音资源的名称，默认 `seed-tts-1.0`；与指定声音的音色编号不同，也不是模型下载地址。 |
| 模型分工 | 用户单独配置的短文本或截图理解模型，负责生成回答；它与只负责朗读回答的播报服务分别设置。 |

## 使用入口

1. 打开“设置 → 语音交互 → 语音播报”。新安装及由旧版覆盖升级后，没有保存在线播报配置时默认选中 Edge TTS，音色为 `zh-CN-XiaoxiaoNeural`（晓晓）。不要求下载播报或克隆模型。
2. 可直接选择“试听音色”。常用音色提供晓晓、云希、曉臻，也可填写服务支持的完整音色编号。修改服务或音色后，先点“保存播报设置”，再试听。
3. 使用火山引擎时，选择“火山引擎”，按控制台提供的凭据选择“API Key”或“App ID 与 Access Token”，填入对应字段。默认使用语音合成 1.0，音色为“湾湾小何”`zh_female_wanwanxiaohe_moon_bigtts`，资源为 `seed-tts-1.0`。已有明确保存的资源和音色不会被新默认值覆盖；此前保存了 2.0 配置的用户，需要在设置中修改并保存后再试听。实际可用性取决于密钥所属项目是否开通对应资源与音色，声音复刻服务单独开通不代表拥有语音合成权限。
4. 已开通音频生成服务时，选择“火山音频生成 1.0”，填写相同来源的接口凭据。默认参考音色为“小何 2.0”`zh_female_xiaohe_uranus_bigtts`；该接口文档支持语音合成 2.0 或声音复刻音色，1.0“湾湾小何”不适用。无需填写语音合成的资源标识。两种火山服务分别保存音色，切换服务不会改写另一项。生成服务按提示词创作音频，应用要求逐字朗读，但实际内容一致性、耗时和计费以该服务为准。
5. 开始语音对话前，先在“设置 → 语音交互 → 系统语音识别”检查服务是否可用，再启动 dsh 并配置聊天模型。没有服务时可进入系统语音设置安装或启用，返回应用后会重新检查。部分手机需要先在系统语音应用中完成首次启用与权限设置。在底栏选择“语音”，识别文字会进入当前 dsh 会话，正式回答逐步显示，并按短分句交给已保存的播报服务朗读，无需等待整轮回答结束。试听不要求启动 dsh，也不要求下载识别模型。
6. 多轮语音页立即显示识别文字，回答生成时逐步补入对应消息。默认开启“语音打断”：回答和播报期间继续使用系统识别服务收音，无需再次说唤醒词；确认插话后停止旧回答，保留本次收音的最终问题。也可点击麦克风“打断回答”按钮。新开关独立于旧版“播报中唤醒”设置，默认开启；保存关闭后会继续保留这一选择。结束语音或切换到文字对话会停止录音、在线合成请求与播放。失败时保留已经得到的文字回答，并显示可操作的错误提示。
7. 按需设置唤醒短语和后台声音唤醒；简单任务与截图理解继续在“设置 → 任务分工”配置。

语音转文字由手机系统服务处理，其联网、录音使用与隐私规则由该服务决定；应用不再下载或运行 SenseVoice。识别文字可能发送至聊天模型，助手回答文字会发送至所选播报服务。模型下载镜像只改变可选本地文字模型的下载来源，与系统识别或在线播报服务没有关系。网络或播报服务不可用时不会换回旧的本地合成方案。

## 自定义分工模型

**模型来源**由用户在原生设置中选择，决定文字或语音中的简单任务交给哪个模型；**服务标识**是聊天设置为一个模型服务保存的名称，用于查找该服务的地址、协议和密钥，与服务侧实际接收的**模型名称**不同。服务地址和密钥仍由现有聊天设置管理，小模型设置只保存服务标识与模型名称。

- **默认本地**：继续使用模型资源区下载的 Qwen3 0.6B。
- **自定义本地**：点击“导入模型”选择手机上的 GGUF 文件；导入成功后自动选择该模型，也可切回默认本地。GGUF 是发布者打包模型权重与元数据的文件格式，需包含当前 llama.cpp 推理库支持的模型架构和对话模板。对话模板是发布者随模型提供的消息排版规则，负责把系统要求、多轮消息和回答起始标记转换为该模型理解的文本，不能直接用 Qwen3 格式替代所有模型。导入会检查文件头、存储空间、加载条件和模板支持，计算摘要后发布；失败或取消保留上一个模型。文件复制到应用私有目录，之后不依赖原文件的读取权限。
- **在线模型**：先在聊天设置中添加服务地址和密钥，再填写对应的服务标识及模型名称，点击“保存任务配置”。保存只检查字段格式；实际服务是否可用、名称是否受支持，以模型请求结果为准。简单任务的会话上下文会发送给此服务，并按该服务规则计费。

分工开关影响文字输入或语音识别后规则匹配到的简单任务，以及任何会话中的 `phone_screenshot` 截图识别；不匹配的文字或语音任务沿用当前聊天模型。选中的模型临时用于这一轮，原模型作为后续选择保留在会话中；结束、失败或取消后恢复原选择，用户在执行期间主动改选模型时以用户选择为准。语音工作期间禁止修改来源或导入文件。

简单任务按内容判断，不以输入方式区分。当前规则覆盖问候、助手身份、简短概念解释及基于上一轮回答的简单追问，例如“你好”“你是谁”“什么是光合作用”“把你的第二点展开说说”。规则先排除超过 160 个字符、手机操作、实时查询、文件、代码、提醒及记忆操作等请求，再与项目维护的示例比较；不明确匹配时使用当前聊天模型。它不是先让小模型判断任意任务的难度。

普通文字消息在正式会话领取输入后，通过已认证的本机连接读取分工配置，再在组装本轮提示词前临时选择模型；语音识别后的文字沿用相同规则与配置。带图片等附件、后台插件消息及同一轮的追加输入不单独分流。本地模型继续检查所需前文是否完整、是否超出短文本预算；不能完整处理的普通上下文沿用原模型，涉及无法完整保留的记忆背景则明确报错，不自动发送到云端。截图和简单文字任务分别读取图片与文本模型配置，独立图片模型不会覆盖简单任务的模型。

本地导入文件最大 4 GiB，仍受设备可用内存和当前推理库能力限制；扩展名正确不代表模型可运行。自定义本地模型读取自身模板，默认模型继续使用原有格式。两者保持相同的短任务上下文与输出预算，加载前的内存检查只是含余量的估算，不是系统内存预留。

**截图识别**可单独填写“截图服务标识”和“截图模型名称”，两项都留空时沿用文本分工模型。服务仍从聊天设置读取地址与密钥，不要求先下载默认文本模型。当前默认 Qwen3 与导入 GGUF 的手机推理引擎仅支持文字；需要通过已配置服务选择支持图片的模型。若服务指向用户自建的本地视觉服务，也通过同一服务配置接入；这与把 GGUF 文件导入手机运行不同。截图分工的能力检查、结果与坐标有效期见[手机能力](phone.md)。

## 请求与播放流程

`VoiceControl` 是由应用对象创建并长期持有的语音协调对象，管理收音、会话、试听、下载与取消。每次语音任务创建 `VoiceOutput` 播报对象；它读取一份已保存配置，并在本次任务内固定使用。界面不允许语音工作期间改配置，未保存草稿不能直接试听，避免界面选项与实际请求不一致。

1. 语音协调对象把识别文字通过本机通信桥交给 dsh。通信桥是宿主与引擎之间、每次启动时建立的认证连接，负责传递请求，不是外部云服务地址。dsh 复用现有会话、工具与历史，沿当前轮次转发正式回答文字的增量，保留会话与最终回答；思考内容和工具调用参数不进入播报。
2. 协调对象一边接收回答、一边积累短分句；遇到句末标点即可提交，较长文本按逗号或最多 120 个 Unicode 码点切分，无标点但积累足够文字时按约 600 毫秒的检查间隔尽早提交。播报对象继续清理 Markdown 标记，跨增量的代码块和链接地址不会读出。Unicode 码点表示完整字符，避免把表情符号的编码拆开。火山音频生成仍需等待每次完整音频响应，不具有 Edge 的音频分块播放能力。
3. Edge 通过 WebSocket 连接逐段返回 MP3。WebSocket 是应用建立的持续双向网络连接，区别于一次提交一次响应的普通 HTTP 请求。应用使用当前版本 2 请求令牌，发送语音格式与经过 XML 转义的朗读文本，解析二进制包头，把音频片段放入有大小上限的接收队列；播报线程持续组装 MP3 帧、解码并播放，收到足够声音后即可出声，无需等待本轮完成标记。MP3 帧是解码器可处理的音频单位，网络包可能把一帧拆开，因此使用同一个解码器处理连续帧，不能把每个网络包当成独立文件播放。完成标记只表示网络音频收齐，应用继续等已写入的声音播放完，避免截断句尾。令牌是协议生成值，与用户的云服务密钥无关。协议参考 [edge-tts](https://github.com/rany2/edge-tts)，适配实现和许可原文随本项目提供。
4. 火山语音合成通过 HTTPS 请求 `https://openspeech.bytedance.com/api/v3/tts/unidirectional`。该接口按 JSON 行陆续返回 Base64 音频片段；Base64 是把二进制表示成文字的编码方式，不是另一种音频格式。应用累积音频，遇到成功结束码 `20000000` 才允许播放；返回错误码、缺少完成标记或音频为空均视为失败。终止包可以没有音频，也可以包含最后一段音频。火山音频生成改用 `https://openspeech.bytedance.com/api/v3/tts/create`，成功响应直接包含 `audio`，没有流式结束码；应用读取完整 JSON 并解码音频，不再请求响应中的下载链接。
5. 播放前申请 Android 音频焦点，即请求系统协调本应用与其他应用的声音。Edge 使用 Android 的 `MediaCodec` 解码器，把 MP3 转成 PCM，再交给 `AudioTrack` 连续播放。PCM 是解码后的声音采样值；`AudioTrack` 由播报对象创建，只负责把这些采样送到声音设备。火山两种服务继续把完整音频临时写入应用缓存，由系统 `MediaPlayer` 播放，结束或取消后释放播放器并删除临时文件。`MediaPlayer` 是 Android 的文件音频解码和播放对象，不在本机合成声音。
6. 用户打断时立即停止当前播放、清空音频队列并取消旧轮次生成；每次回答使用独立编号，迟到的文字、音频和焦点回调不能恢复上一轮。工具执行中的文字进度也可能先被播报，最终文字消息仍显示实际最终回答；每条回答沿用最多 4000 码点，整轮增量另设 16000 码点上限，防止多次工具步骤积累无界。用户结束语音、永久丢失音频焦点或设备变化时停止当前请求与播放。系统识别服务临时申请焦点时不直接结束整个对话。请求和播放有等待上限，单段音频限制为 8 MiB。音频生成使用独立的 180 秒等待上限，其他服务沿用 90 秒总请求上限；等待期间可随时停止。音频生成连接中断后不自动重发，避免重复生成与计费。网络异常显示连接中断或超时提示，诊断日志仅记录异常类型。服务报错不直接展示响应正文或凭据，文字会话继续保留。

火山语音合成请求固定传入 `user.uid`，以及 `req_params.text`、`req_params.speaker`、`audio_params.format=mp3`、`audio_params.sample_rate=24000`，请求头携带资源标识。火山音频生成请求传入 `model=seed-audio-1.0`、`text_prompt`、`references[0].speaker`、`audio_config.format=mp3`、`audio_config.sample_rate=24000`，不携带语音合成的资源标识。提示词用 `@音频1` 引用参考音色并要求逐字朗读回答。两种请求均有独立请求编号；API Key 模式只携带 `X-Api-Key`，旧凭据模式只携带 `X-Api-App-Id`、`X-Api-Access-Key`。不混用两种凭据，也不向重定向地址转发。

在线播报配置保存在应用私有的 `voice-output` 偏好设置中，与旧的 `voice` 设置分开。旧音色选择不会覆盖新默认值；本次升级不删除设备已有的参考录音、克隆模型或备份，因此切回归档分支仍可继续检查原方案。系统卸载与清除应用数据仍会清除这些私有数据。

## 实现文件

| 文件 | 创建方与职责 |
|---|---|
| [`VoiceControl.kt`](../app/src/main/java/local/dshx/app/VoiceControl.kt) | 应用创建的语音协调对象，维护会话、识别文字、回答、下载状态及任务取消。 |
| [`VoiceInput.kt`](../app/src/main/java/local/dshx/app/VoiceInput.kt) | 协调对象为任务创建的收音对象，在手机执行关键词唤醒，并在主线程创建、调用和释放系统识别对象；后台任务等待最终文字、超时或取消。 |
| [`VoiceService.kt`](../app/src/main/java/local/dshx/app/VoiceService.kt) | Android 创建的麦克风前台服务，显示持续通知，并在设备变化时停止任务。 |
| [`VoiceOutput.kt`](../app/src/main/java/local/dshx/app/VoiceOutput.kt) | 协调对象创建的在线播报对象，保存及校验服务配置，处理 Edge、火山协议、音频缓存、播放与取消。 |
| [`EdgeToken.kt`](../app/src/main/java/local/dshx/app/EdgeToken.kt) | 播报对象调用的 Edge 请求令牌生成器，按协议计算版本 2 令牌，不保存账户密钥。 |
| [`VoiceModels.kt`](../app/src/main/java/local/dshx/app/VoiceModels.kt) · [`voice/models.json`](../app/src/main/assets/voice/models.json) | 唤醒与可选文本模型的安装器与固定清单，检查下载大小和摘要；不再包含整句识别、语音分句、播报、克隆或降噪模型条目。升级时清理旧 SenseVoice 模型目录及其临时目录，保留唤醒和文字模型。 |
| [`SmallModel.kt`](../app/src/main/java/local/dshx/app/SmallModel.kt) | 宿主创建的分工模型配置与自定义文本模型管理对象，独立于在线播报。 |
| [`voice.mjs`](../core/voice.mjs) | dsh 内的语音接入与简单任务分工模块；文字和语音共用任务规则，保持正式会话历史与临时分工模型的恢复规则。 |
| [`LocalModel.kt`](../app/src/main/java/local/dshx/app/LocalModel.kt) · [`local.cpp`](../app/src/main/cpp/local.cpp) | 只负责可选的本机文本推理，不负责朗读。后者通过 llama.cpp 执行文本模型；llama.cpp 是构建时准备的 C/C++ 文本推理库。 |

唤醒使用 sherpa-onnx 的关键词模型；sherpa-onnx 是应用集成的本机执行库，此处只检测用户保存的唤醒短语，不再执行整句语音转文字。整句收音、讲话结束判定和转文字均交给 Android 系统识别服务，应用通过 `RecognitionListener`（系统调用的识别状态与结果回调）取得音量、收音状态、错误和最终文字。中间识别结果用于判断用户是否插话，不作为最终问题发送。系统“开始说话”和音量回调不直接触发打断。应用先排除播报回声、纯标点及孤立的“嗯／啊”等填充音；普通中间文字需要至少两个有效字符，两次真实文字回调保留一致的开头，且间隔至少 300 毫秒，才确认插话。最终识别结果仍可接收“好”“不”“停”等有效单字，之后继续使用同一个识别器取得完整问题。这是文字层面的回声过滤，不代表系统服务提供了声学回声消除；不支持中间结果的服务可能要等最终结果才能打断，用户复述助手原话也可能被视为回声。扬声器音量、识别服务和设备环境会影响效果，可用页面麦克风按钮直接打断。自动插话识别单独报错时，停止这次监听并提示改用麦克风按钮，回答生成和播报继续；手动打断后再尝试新一轮收音。模型生成失败会立即停止正在合成和播放的声音，保留已收到的文字并标记“部分回答”。只有初始后台声音唤醒仍使用本地关键词检测；语音打断本身无需唤醒模型。停止时在主线程取消并释放识别对象，后台任务有界等待清理完成，再允许下一轮收音；迟到回调不影响下一轮。服务准备好后才开始计算无声输入期限。有有效中间文字后，若 1800 毫秒没有新增有效字符，应用在主线程复查后调用系统 `stopListening()`，即停止继续收音并请求已收录声音的最终结果，不是取消并丢弃录音。重复文字、标点变化、等长改写、回声和音量变化不能延长该期限。它是文字进展停滞的保护，不是声学语音结束检测；口述中的长停顿或服务迟迟不更新文字仍可能提前收尾。结束后最多等待最终结果 5 秒，不将中间文字自行当作最终问题。仅报告语音开始、从未返回非空中间文字的服务仍沿用整轮 60 秒上限，以免把仅返回最终结果的长句直接按 5／8 秒无输入截断；当服务已经返回中间文字但全部为回声或标点时，仍按原无输入期限退出。首次等待、无声输入、等待最终结果和整轮任务均有时间上限。连续对话只对无匹配或无声结果结束等待，网络、权限、服务占用等故障仍明确报错。应用不会偷偷切回本地识别。

接入方式对照 `gongpx20069/hi-mochi` 的 `AndroidVoiceRuntime.kt`，参考提交 `8a1756087d1306c0d05e2b6b3a667c1ed06ec800`：采用标准的设备端能力判断、默认系统服务和主线程生命周期管理；不使用参考实现中的小米私有参数。采用相同系统接口不代表所有品牌都提供可用服务；实际语言、联网需求和后台行为仍需在各手机验证。
