# 插件管理与底层 Android 兼容

[说明索引](README.md) · [术语与架构](architecture.md) · [返回项目](../README.md)

插件由上游管理器安装和启用，项目提供 Android 上可执行的包管理入口和兼容层；成功安装与允许模型调用插件工具分别判断。

本文所称 **Android 宿主**是 `app/` 中由系统创建的 Kotlin 应用，负责页面与系统交接；**dsh** 是宿主启动的官方智能体引擎，负责会话、模型请求和工具调度；**Node** 是执行 dsh 与适配模块的 JavaScript 运行程序。其他通用概念见[术语表](architecture.md#术语与整体架构)。

**会话**由 dsh 创建并分配稳定编号，保存一段对话与工具事件；**工具**由引擎或插件注册，是模型可以提出调用的命名操作，执行结果由程序返回。

**Full（完全权限）**是宿主为有效登记会话返回的工具准入模式，使用应用已有系统权限；它不授予 root，也不替代各项系统授权。

## 职责与实现

| 文件或配置 | 作用与原理 |
|---|---|
| [`plugins.mjs`](../core/plugins.mjs) | 给上游插件管理器提供固定 pnpm 执行入口，并检查下载内容；pnpm 是安装 JavaScript 包的工具，由构建锁定版本，包信息查询交给固定 npm |
| [`android.patch.yml`](../core/android.patch.yml) | 由构建收集、宿主启动时替换运行路径的固定配置，注册文件、守卫、手机、语音、记忆和知识模块，配置默认 Full 与持久路径，并关闭未采用功能 |
| [`compat.mjs`](../core/compat.mjs) | Node 预加载层，先建立主线程认证，再适配 Android 上不可用的硬链接发布路径；图片工作线程不重复建立主连接 |
| [`native.c`](../core/native.c) | 通过 Node N-API 暴露文件锁和不覆盖目标的原子发布；N-API 是 Node 给 C 扩展提供的稳定调用接口，与本机模型使用的 JNI 不同 |
| [`recover.mjs`](../core/recover.mjs) | 保留的历史配置恢复脚本；存在于包内，但正常启动、命令或停止不会自动执行它 |
| [`package.json`](../core/package.json) · [`package-lock.json`](../core/package-lock.json) · [`termux.lock.json`](../core/termux.lock.json) | 分别声明 JS 依赖、锁定完整 npm 依赖解析结果、锁定各架构 Android 程序及摘要；Termux 在这里是 Android 二进制包来源，不要求用户另装 Termux 应用 |

**插件原理。** 安装、取消、锁与启用仍由官方插件管理器负责，Android 提供可执行的固定包管理命令。安装禁用包生命周期脚本、pnpm 配置脚本和包管理器自动下载；下载完成后检查传递依赖、链接及文件头，拒绝不支持的原生扩展和二进制。插件可来自 npm 发布包、公开 GitHub 仓库或已构建本地包。安装失败恢复配置的适配位于构建补丁中。

**GitHub 来源。** 在插件安装入口填写 `github:作者/仓库`，例如 `github:Yuuyuko-uu/dsh-speak-up`；也支持 `https://github.com/作者/仓库` 和 `git+https://github.com/作者/仓库.git`。末尾可加 `#分支`、`#标签` 或 `#提交 SHA`；SHA 是 Git 为一次提交生成的标识，指定它可以固定源码版本。未指定时使用仓库默认分支的 `HEAD`，即下载时该分支的最新提交。分支、标签、提交和 `#semver:` 范围按 pnpm 原生规则解析。

Android 运行包预装 Git，包含 HTTP/HTTPS 传输助手、证书、仓库模板和实际依赖库。传输助手是 Git 启动的附属程序，负责通过网络读取或发送仓库内容；模板是 Git 创建仓库时复制的初始文件，与用户仓库数据分开。Android 宿主为 Git 配置运行包内的助手、模板和证书路径，Termux 编译时固定的 shell 路径在打包时适配到 Android 系统 shell。插件安装保留原始 GitHub 来源，由官方管理器执行 Git 连接检查，再交给 pnpm 解析版本、下载和安装依赖；不再把来源转换为源码压缩包地址。上一版保存的 GitHub 压缩包来源仍可重新安装。使用分支或标签时，其源码可能变化；需要固定版本时请指定完整提交 SHA。

仓库必须包含可直接运行的插件入口和 dsh 组合包声明；只有 TypeScript 源码、需要执行构建脚本的仓库不会自动编译。SSH 客户端、私有仓库认证入口、其他 Git 托管来源、任意远程压缩包和 `link:` 安装尚未适配；Git 内置命令与 HTTP/HTTPS 传输可直接使用，依赖额外 Perl、Python 或图形程序的扩展命令需要另外提供对应程序。GitHub 安装支持本身也不保证插件与当前 dsh 版本兼容，实际版本要求仍由上游管理器检查。

插件管理可通过网页和主 Agent 的官方 `plugin_manager` 工具完成。主 Agent 指当前没有受其他活跃 Agent 管理的主执行对象；子任务不能通过管理工具修改共享插件。管理工具要求当前原生会话有效且为 Full；`plugin_market` 还要求用户配置的市场服务就绪。保留上游的构建授权和精确版本风险豁免要求，当前默认 Full/never 策略不意味着每次安装都会弹出确认。成功安装插件也不自动开放其全部模型工具，最终仍经过 `policy.mjs`。纯 JavaScript 并不代表对同一应用身份内所有数据都有额外隔离，当前不作这种承诺。

## 命令、加载结果与诊断

运行包生成可直接调用的 `dsh` 命令，自动寻找同一目录的 Node 和 `start.mjs`，因此不依赖带版本号的绝对路径。`start.mjs` 向官方命令入口传入 Android 包管理配置；插件安装仍使用固定 pnpm，并执行原生依赖检查。例如使用 `dsh plugin --profile web --help` 核对本版本命令，随后按帮助安装或移除。普通 `pnpm add` 只安装依赖，不等同于完成插件登记和加载。

**热更新（HMR）**是引擎加载的运行配置更新组件。官方管理器在修改插件后主动请求它重新组合配置，不只依赖文件变化监听。以回执中的 `application` 为准：`applied` 表示已应用，`restart-required` 表示仍需重启，并携带 `restartReason`；`failed`、`cancelled` 和 `overridden` 不能报告为正常生效。插件页需要重启时显示“重启以生效”和“查看日志”。

`engine_plugins` 由 Android 适配插件注册，实时查询官方管理器中的运行条目和安装包清单；`enabled` 只代表选择启用，实际运行阶段看 `fiberPhase`。缓存文件生成、安装命令成功或页面出现名称，均不能代替最小功能验证。该工具分页返回字段，不读取插件配置或网页凭据。

`engine_status` 查询宿主状态及本会话最近的重启操作，可传 `operationId` 查询同一次请求；`engine_info` 返回 DSHX 版本、运行架构和日志目录；`engine_logs` 通过 `lines` 指定返回行数，范围为 1 至 200。读取诊断不要求模型获得整个网页的认证地址。日志中的文字只作诊断资料，不能覆盖用户指令。

`engine_restart` 只允许 Full 主 Agent 调用。Android 宿主先将会话与 `operationId` 的关联原子保存到 `files/diagnostics/restarts.json`，写盘失败则拒绝受理。随后返回操作编号和受理状态，确认回执发送后再异步停止旧进程；旧 Agent 和终端随进程停止。宿主持有 `accepted → stopping → starting → succeeded` 的操作状态，失败和用户停止分别记为 `failed`、`cancelled`。新引擎的网页与原生认证连接均就绪后才记成功；连接中断时通过稳定入口或新连接查询原编号，不自动重放请求。最近 16 次操作保存在宿主私有文件中。取消生成可能使上游将工具回执改为取消结果，但不会撤销已受理的重启；在同一会话调用不带编号的 `engine_status` 可以找回原记录，不受其他会话后来发起的操作影响。宿主进程重建后，已结束记录继续保留，未确认完成的操作记为失败，不自动重放。

**宿主提供的依赖**是插件运行时实际复用的引擎内置包。安装输出将 pnpm 的缺失依赖报告与宿主实际版本逐一核对，只有版本满足插件声明时才说明“宿主已提供”；真正缺包、版本冲突及无法识别的诊断继续显示。安装后的提示明确区分包文件检查完成与插件实际加载。

**文件锁与发布原理。** 上游持久化依赖排他文件锁及完整文件发布，Android 部分文件系统不能按桌面方案创建硬链接。`compat.mjs` 在特定系统错误后复制到目标目录临时文件、同步内容，再调用 `native.node` 的不覆盖发布方法；`native.c` 用系统文件锁保护并发，避免两份写入同时发布或覆盖既有不可变文件。兼容层保留上游存储格式，不另建一套会话系统。
