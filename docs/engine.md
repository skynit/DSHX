# 应用生命周期与引擎管理

[说明索引](README.md) · [术语与架构](architecture.md) · [返回项目](../README.md)

解释应用启动时谁创建引擎、后台服务如何持有它，以及停止与故障恢复的区别。

本文所称 **Android 宿主**是 `app/` 中由系统创建的 Kotlin 应用，负责页面与系统交接；**dsh** 是宿主启动的官方智能体引擎，负责会话、模型请求和工具调度；**Node** 是执行 dsh 与适配模块的 JavaScript 运行程序。其他通用概念见[术语表](architecture.md#术语与整体架构)。

**会话**由 dsh 创建并分配稳定编号，保存一段对话与工具事件；**工具**由引擎或插件注册，是模型可以提出调用的命名操作，执行结果由程序返回。

## 使用入口

在“工作台”选择“启动 dsh”，等待真实运行状态后进入聊天。“停止服务”结束本次运行；它保留会话和工作文件。页面重建、切换标签与重新启动引擎是不同动作，后文分别说明。

## 职责与实现

**入口与持有关系。** Android 根据应用清单创建 `DshApp`，它按需创建一份 `Engine` 和一份 `VoiceControl`。后者是语音状态协调对象，后文单独说明。页面重建只重新订阅状态，不重新创建第二个引擎。

| 文件或组件 | 作用及协作方式 |
|---|---|
| [`AndroidManifest.xml`](../app/src/main/AndroidManifest.xml) | 向 Android 声明应用、页面、前台服务、无障碍服务、文件分享入口与所需权限；声明权限不等于用户已经授权 |
| [`EngineService.kt`](../app/src/main/java/local/dshx/app/EngineService.kt) 中的 `DshApp` | 持有应用进程共享的引擎和语音状态，避免把生命周期绑定到某一张页面 |
| 同文件中的 `EngineService` | 接收启动、停止操作，建立常驻状态通知并观察引擎状态；应用进程被系统回收后允许系统重建服务，dsh 子进程退出后按延迟重新启动 |
| [`Engine.kt`](../app/src/main/java/local/dshx/app/Engine.kt) | 在后台串行执行安装、启动、读取输出和停止收尾；向页面发布阶段、地址、备份和文件传输状态，完整收尾后向服务返回是否可以重新启动 |
| [`EngineRecovery.kt`](../app/src/main/java/local/dshx/app/EngineRecovery.kt) | 保存实际异常标记 `.trust-pending`，并在启停时核实、结束属于本应用的残留子进程；不负责绘制页面或保存会话 |
| [`launcher.c`](../core/launcher.c) | 编译成 `dshx-run` 启动器，在执行 Node 前绑定宿主死亡信号；宿主进程消失时结束直接 Node 进程 |

**启动原理。** 用户启动前台服务后，`Engine` 先处理残留进程，再读取包内运行清单并检查设备架构。普通重开复用已安装运行环境；首次安装、版本变化或故障恢复时进入完整校验。随后准备用户目录，迁移旧数据路径，读取助手设置，写入本次 Android 适配配置，生成新的启动实例和认证信息，再通过 `dshx-run` 执行 Node。

Node 使用 `--import compat.mjs` 先加载兼容层，再执行 [`start.mjs`](../core/start.mjs)。这个入口从运行包加载官方 `runCli()`，传入 Android 内置包管理程序配置，按宿主参数进入 dsh 网页模式。网页服务只监听 `127.0.0.1`，即本机回环地址，使用随机端口和启动认证。宿主仅接受符合固定格式的就绪地址交给 WebView；诊断显示脱敏后的日志，不直接展示认证地址。

**停止与失败。** 用户停止会撤销通信、请求结束进程，超过等待时间后强制结束并核实残留。完整收尾结束后才允许下一次启动。正常停止保留配置、会话和工作文件；实际故障才标记下一次检查。`EngineRecovery` 不在每次正常命令后重建用户配置。`dshx-run` 的父进程绑定直接保护 Node，所有后代进程的收尾还需引擎的进程核实，不能仅凭启动器推断全部子进程已结束。

**自动重启。** 服务启动后向 Android 返回 `START_STICKY`，即请求系统在应用进程被回收后重新创建仍处于启动状态的服务；系统可以用空的启动请求调用它，服务会重新启动引擎。该机制由 Android 调度，不保证立即恢复，也不能绕过用户在系统设置中的强行停止。它不包含手机重启后的开机启动。

应用进程仍在、只有 Node 子进程退出时，`Engine` 先撤销本次通信、结束残留进程并发布结束状态，再通知服务重新启动。服务从 1 秒开始等待，连续退出时依次等待 2、4、8、16、32 秒，最多 60 秒；引擎就绪后连续运行至少 60 秒，下一次退出重新从 1 秒开始。每次启动重新生成运行实例和认证信息，旧手机动作不会由服务排队重放。插件自身恢复任务的行为仍由该插件决定。

用户点击页面或通知中的停止时，服务先取消待重启回调，并返回 `START_NOT_STICKY`；进程在停止收尾期间被回收，也不会因此重新启动。服务销毁时同样撤销回调。运行包准备失败、备份正在进行，或无法确认残留进程已结束时停止服务并保留错误状态，不反复重启。重新启动服务需要用户明确操作。

## 任务执行期间的后台保活

**任务执行状态**来自 dsh 的会话执行对象（Agent，由引擎为会话创建，负责模型请求和工具执行），与“引擎已启动”不同。`guard.mjs` 是运行配置加载的 Android 适配插件，在现有会话登记与权限检查之外汇总正在执行的 Agent；普通聊天、语音进入的正式会话、实验体培养和子任务均按真实运行状态计入。模型请求之间不会释放保活资源；有多个会话同时执行时，直到最后一个回到空闲或销毁才释放。尚未开始执行的排队消息不单独触发保活，独立的资料索引和记忆整理也不冒充会话任务。

**状态传递。** `PolicyHost` 是 Node 侧的本机通信对象，`PolicyBridge` 是 Android 侧接收对象；两者共用已有、验证运行实例和令牌的连接。`guard.mjs` 用 `task-state` 消息发送汇总后的布尔状态，Android 严格检查字段和类型，再交给 `Engine` 发布 `taskRunning`。只有汇总状态变化才发送消息，不根据页面是否打开推断任务状态。

**资源管理。** `EngineService` 在自身运行且 `taskRunning` 为真时调用 `TaskPower`。这是服务创建的后台资源管理对象，负责以下两项资源，不负责启动、重试或恢复任务：

- 向系统电源管理器申请 `PARTIAL_WAKE_LOCK`，即允许屏幕关闭、请求处理器继续工作的部分唤醒锁。每次申请有效十分钟，任务仍在执行时每五分钟续期；这不是十分钟任务上限。若续期线程停止响应，唤醒锁到期后自动释放。
- 通过 Android 的 `AudioTrack`（应用创建的原始音频播放器）加载一秒全零 PCM 数据。PCM 是未压缩的音频采样；此处使用 8000 Hz、单声道、16 位数据，共 16000 字节，按完整 8000 帧无限循环，并将播放器音量设为零。静音在内存中生成，不需要下载或保存音频文件；不申请音频焦点，也不修改系统媒体音量。

最后一个任务结束或取消后释放唤醒锁和播放器，并撤销续期。服务停止、销毁、子进程退出或认证连接断开也会清理资源。音频创建或播放失败只记诊断日志，保留可用的唤醒锁，并在下次续期时尝试恢复音频；不会因此取消用户任务。

**能力边界。** 该功能用于降低任务息屏时暂停的机会，不能保证进程不被系统或厂商策略回收，也不能阻止用户强行停止。系统深度休眠仍可能限制网络或忽略唤醒锁，静音输出是否持续由设备音频与电源策略决定。引擎自动重启与正在执行任务的继续执行是不同能力，本功能不自动重放已经发出的手机动作或工具调用。只在真实会话任务期间启用，空闲的引擎不会持续播放静音或持有此任务唤醒锁。

## 后台托管

运行包内置的 `hosting.mjs` 在引擎运行期间提供约五分钟的本地概率检查，命中后交给正常会话执行。它通过只读手机状态查询跳过锁屏、息屏和无障碍未就绪的机会，不积压历史任务。配置、独立会话与结果记录见[后台托管与概率触发](hosting.md)。
