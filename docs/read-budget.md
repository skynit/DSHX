# 共享读取额度与知识任务控制

[说明索引](README.md) · [术语与架构](architecture.md) · [返回项目](../README.md)

共享读取额度由记忆和知识模块共同维护，限制同一次真实用户请求或实验体培养机会读取的资料量；后台业务任务另用操作编号与任务编号跟踪。

本文所称 **Android 宿主**是 `app/` 中由系统创建的 Kotlin 应用，负责页面与系统交接；**dsh** 是宿主启动的官方智能体引擎，负责会话、模型请求和工具调度；**Node** 是执行 dsh 与适配模块的 JavaScript 运行程序。其他通用概念见[术语表](architecture.md#术语与整体架构)。

**会话**由 dsh 创建并分配稳定编号，保存一段对话与工具事件；**工具**由引擎或插件注册，是模型可以提出调用的命名操作，执行结果由程序返回。

**工作区**是宿主准备的默认任务目录，也用于筛选项目资料与记忆；它与整个应用私有数据目录分开，不自动构成文件隔离。

**token** 是模型计算文本用量的单位，由实际模型或服务报告；它与字符数、UTF-8 字节数不同，读取额度中的字节预算也不是实际计费用量。

## 职责与实现

**为什么共用额度。** [`read-budget.mjs`](../core/read-budget.mjs) 是记忆与知识模块共同调用的读取计量器，由两套模块在同一个 dsh 根上下文中取得共享状态。它防止同一个问题通过切换工具、关闭重开模块或重建智能体重复领取容量；不是用户手动管理资料的限额器。

读取请求由真实会话最近一条有效业务输入确定：真实用户消息 `source.kind=user`，或带有机会编号的实验体消息 `source.kind=plugin:dshx-hosting`。运行时背景、其他插件和记忆注入不创建新额度。该请求内 `memory_search` 与 `knowledge_search` 合计最多 3 次，`memory_read` 与 `knowledge_read` 合计最多 6 次，`knowledge_list` 最多 1 次；返回 JSON 总量按实际模型上下文余量计算，最多 4096 UTF-8 字节。并发调用先预留额度，返回前重新解析模型、检查请求头与工作区、核对来源，再结算实际字节，避免同时读资料时超额。完整记忆放不下时拒绝，不把截断正文冒充完整结果。

**知识业务有三类编号。** 通信请求编号由通信桥生成，只匹配一次等待；`operationId` 由管理端创建，代表一次导入、重建或删除等用户操作；`jobId` 由 Node 知识模块创建，代表实际后台任务。任务分别记录阶段、执行状态和正式效果，进度到达某处不等于原文或索引已经发布。

操作去重保存 24 小时，相同操作编号与参数不会重复执行，改参数会拒绝。等待超时或关闭管理窗口只结束当前等待，业务可能已受理，应查询原操作；明确取消要带任务编号。发布前取消可以阻止发布，发布后取消只结束剩余加工；已发布原文保留。进程中断后未完成的加工等待用户继续，删除清理可以自动恢复，避免重启立即重复云端调用。

当前容量为 100 份有效文档、100 个集合、单文档 2 MiB、原始文件合计 50 MiB、总分块 5000、每文档 500 块。容量限制、任务保存和并发版本检查共同约束内存与磁盘；它们不代替目标设备上的性能验收。
