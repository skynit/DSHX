# 公共端点使用 P2P 优先的穿透聊天

DSHX 穿透聊天将端点默认设计为公共目录对象：已发布端点可以被平台上的其他已登记端点发现并尝试连接，端点用户可以用隐身、暂停、限频和并发上限控制接入。业务数据优先通过 WebRTC 的端到端数据通道传输；平台提供中继凭据时，也可以由 TURN 服务器转发加密数据。穿透平台负责目录、信令和中继，不保存聊天正文或附件。DSHX 复用 CWNAS 的信令格式，不复用透明 HTTP 协议；聊天端点身份由 DSHX 客户端独立验证。[穿透聊天](../tunnel-chat.md) 记录平台契约与当前实现边界。

WebRTC 数据通道只负责承载无序、零重传的数据报。端点在其中运行 QUIC v1 和 HTTP/3，把可能耗时的图片请求和文字流分开，并用绑定当前连接的签名 token 双向验证端点。此变更不改变平台信令和中继边界；旧客户端聊天传输不兼容。
