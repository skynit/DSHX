# 广告跳过：一种微应用用途

广告跳过只是验证后台脚本和手机能力的示例。普通应用可以完全没有这些接口，不要把平台变成广告规则解释器。

参考 GKD 的价值是：让用户创建功能，界面事件唤醒逻辑，利用真实组件树找到目标，并控制等待和重复动作。本示例不导入 GKD 订阅，也没有复制其代码；用户要求兼容时须另行核对格式和功能，不能宣称现有脚本已经兼容。

从 [完整示例包](../assets/skip-startup-ads.json) 创建草稿。它包含独立页面、可测试匹配函数 `match.js` 和后台脚本 `background.js`：

1. 用户在宿主选择作用范围、启用应用并授权无障碍服务。
2. 后台脚本监听 `dshx.screen.onChange`；同一时刻只处理一次，动作后冷却5秒。
3. 请求完整组件树，要求独立“广告”证据与唯一“跳过”入口。按钮文字可以带倒计时。
4. 证据与目标不能共用整个广告可点击容器；多个跳过候选、不完整文字或树均不点击。
5. 使用本次 `snapshot` 和真实 `clickTarget` 调用点击。仅保存动作回执文字，明确不等于业务成功；异常不自动重试。

这是保守示例，不能代表识别所有广告。真正适配某个应用时应先观察真实页面，优先结合稳定控件标识、布局关系、应用范围和明确页面证据。按需要扩展普通 JavaScript 匹配逻辑，不要求宿主为每种广告新增协议字段。

至少验证：正常广告、普通引导中的“跳过”、多个候选、同一广告容器、文字截断、锁屏、手机总开关关闭、聊天正在操作、离开允许范围、停用应用后无新动作。测试应在用户允许的应用范围内进行，不用真实业务按钮冒充广告按钮。
