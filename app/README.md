# DSHX Android 宿主开发包

界面继续沿用现有架构：工作台和原生设置由 Kotlin Compose 与 Miuix 实现，原生图标统一使用 Lucide；聊天由 WebView 加载锁定版本的官方 dsh React 页面。`chat.css` 将官方页面的语义颜色变量、圆角、输入框、菜单与键盘焦点统一为 Qoder 风格，明暗配色与原生主题一致。颜色变化使用短过渡，网页响应系统减少动态效果设置；原生选中态与输入框焦点使用 Compose 动画。两个界面仍各自使用已有的主题偏好入口，没有新增主题存储。

shadcn/ui Nova 的紧凑控件可以作为视觉参考，但没有为本轮换肤引入 shadcn/ui、Motion、react-resizable-panels、dnd-kit 或 Zustand。它们属于网页实现层的选择，不能直接替换 Kotlin 控件；现有页面没有需要新增分栏调整或拖拽的流程。聊天继续使用官方编辑器、图标、状态与交互实现，后续确需维护自己的网页组件时再按实际功能选择依赖。

## 当前实现与职责

| 名称 | 它是什么、由谁创建、负责什么、与相近概念的区别 |
|---|---|
| `DshApp` | Android 创建的应用对象，持有一份共享 `Engine`；页面重建不会创建第二个引擎 |
| `Engine` | 应用创建的运行管理对象，在后台安装或复用资源、启动停止 Node、发布状态和脱敏日志；不绘制页面 |
| `EngineService` | 用户启动后由 Android 创建的前台服务，通过通知显示状态并提供停止；管理生命周期，耗时工作由 Engine 的后台线程执行 |
| `CoreStore` | Engine 创建的离线运行包管理器；`installed()` 快速检查收据和启动文件，`current()` 完整核对目录，`install()` 在必要时解包发布新目录；会话不放在运行包内 |
| `MainActivity`／`DshScreen` | Android 页面入口及应用的管理界面，订阅真实状态；前者创建 WebView、处理文件选择与页面错误，后者显示工作台、聊天、设置和按需诊断 |
| `WebView` | Android 系统提供的网页组件，由宿主创建以显示原版聊天；网页渲染进程不是 dsh 引擎本身 |
| `ToolPolicy` | Engine 创建的当前运行会话记录，登记实例与父子归属，所有合法会话统一为 Full；不是逐会话权限设置器，不持久保存聊天内容 |
| `PolicyBridge`／`host.mjs` | 前者由 Engine 创建本机认证 TCP 长连接服务，后者是 Node 侧客户端；负责登记、查询、结束会话，以及手机操作与匹配取消；不是 HTTP 服务，不负责安装插件 |
| `PhoneControl`／`PhoneService` | 前者由 Engine 创建，保存独立手机操作开关并排队执行请求；后者是用户在系统设置授权后由 Android 创建的无障碍服务，负责真实读屏、控件动作与截图；Full 会话权限不替代手机开关或系统授权 |
| `EngineRecovery` | Engine 创建的故障标记与残留进程处理组件；记录的实际故障才要求下次完整检查，正常命令与停止不标记配置重建 |
| `dshx-run` | 构建时编译的启动程序，绑定宿主死亡信号后执行 Node；保护直接引擎进程，不能据此承诺所有后代进程立即结束 |

启动顺序：用户请求前台服务 → Engine 在后台读取包内清单、核实并清理残留进程 → 普通启动快速检查安装收据与固定启动文件；首次安装、更新或记录的故障执行完整检查／必要的离线重装 → 保留并使用 `home`、`workspace` 与临时目录，写入固定 Android 适配补丁 → 创建本次宿主认证连接 → 经 `dshx-run` 启动 Node 的 `start.mjs` → 启动入口给上游指定内置包管理程序并运行原版网页 → 宿主读取本机认证地址供聊天页加载。固定补丁更新不同于重建用户的模型配置或会话。

安装和启动可以取消；停止先请求结束，超时后强制结束并核实应用所属进程，完成收尾后才允许下一次启动。页面切换不停止服务，宿主服务被系统结束后不自动恢复模型任务。已有 ARM 包的短时亮屏后台记录不能扩展为锁屏、长时待机或全部厂商系统均通过。

## 界面设计

- **工作台**：显示实际状态、启动与停止、聊天入口及按需诊断；安装阶段显示真实进度。
- **聊天**：保留原版网页；网页组件须为 Chromium 126 或更新版本。未安装、版本过低、页面错误或渲染进程异常分别说明，服务继续状态与网页状态分开。
- **设置**：持久保存管理页的跟随系统、浅色、深色选项；编辑并保存助手名字、身份和提示词，恢复上游默认设置。提供手机操作开关、系统无障碍设置入口与状态刷新；展示默认完全权限的实际含义和版本。按用户要求移除原生用量统计区域，后台调用账本继续保存供验收使用。不提供原生逐会话 Full 开关；聊天外观在 dsh 内设置。
- **诊断**：按需显示最近 120 行，每行有长度上限，可选择文本；隐藏启动 token、常见 API key 和认证头，不承诺识别任意敏感文本。

原生管理界面参考 Qoder 的暖中性色、细边框与低强调选中态。工作台、设置、诊断和底部导航共用背景、文字、边框和状态颜色，支持浅色与深色；基础按钮沿用 Miuix，输入框使用 Compose 原生文本编辑组件。原生触控高度至少 48dp，内容在宽屏居中并限制阅读宽度。系统使用大字体时，底部导航仅显示文字，避免标签被图标挤压。

助手人设保留名字、身份、提示词及 DS 默认内容，使用短说明、框外标签和同行的保存／恢复按钮。字数仅在编辑或超限时显示，超限错误紧邻字段；默认页面不常驻显示编码单位说明。外观选项改为同行的跟随系统、浅色、深色三个选项。各页面滚动位置和未保存草稿沿用原有管理方式；手机输入布局的历史证据见下方对应构建记录。

## 运行环境与数据

构建入口是 `tools/core.py`，输入包括 npm 锁文件和 `core/termux.lock.json`；APK 资源是 `core.zip`、`core.json` 和 `core-info.json`。原生文件采用 Android NDK 编译或已锁定的 Android 包，检查 16KB 对齐。N-API 是 Node 提供的稳定扩展接口，本项目用它实现文件锁和原子发布，并编译官方 node-pty 终端模块；对齐检查不等于原生 16KB 设备已通过。

首次安装校验压缩包与每个文件，完成后在独立版本目录写入安装收据 `.verified`。普通重开不枚举全目录、不逐文件计算摘要；只检查收据及固定启动文件的存在、大小、执行位。故障修复完整检查目录和文件摘要，必要时重新解包；不自动调用 `recover.mjs` 重建用户配置。`recover.mjs` 是保留的历史恢复脚本，它存在不代表默认会执行。

暂存仅在完整成功后激活，取消和失败清理暂存。目录包含运行包摘要，同一上游版本的新构建不会覆盖其他构建；旧运行目录没有自动回收或一键回退入口。快速启动不会发现所有同大小篡改，当前不承诺同一应用身份内的恶意代码隔离。

- 运行包：`files/core/<version>-<archive-hash-prefix>/`。
- 用户目录：`files/home/`；模型配置、凭据、会话和附件由上游放在其中。
- 工作区：`files/workspace/`，作为默认目录，不是 Full 的隔离边界。
- 引擎临时文件：`cache/engine/`。

资源体积以 DELIVERY 对应包记录为准，更新保留旧版本还需额外空间。覆盖安装同签名包可保留私有数据；卸载或清除应用数据会删除它们。宿主重新构造子进程环境，不继承开发机凭据或 Node 注入参数。网页仅监听本机随机端口并要求启动认证，模型请求仍需网络。

## 文件工具、附件与手动终端

| 名称 | 它是什么、由谁配置、负责什么、与相近概念的区别 |
|---|---|
| `policy.mjs` | 运行包内的 Android 固定准入规则，由宿主配置工作区与查询连接；开放 read/write/edit/glob/grep、前台 bash 和十项 phone_* 手机工具；其他未适配工具继续拒绝 |
| `AndroidFiles` | Android 固定补丁注册的文件服务，保留上游原子写入和旧版本检查；Full 使用应用可访问路径，旧受限模式分支仍保留给兼容测试，不提供页面开关 |
| 异步调用上下文 | Node 为每条异步调用保存的独立状态，由实际工具入口建立，区分模型文件操作与引擎自身读取配置；不是全局共享开关 |
| rg | 构建时内置的 ripgrep 文件搜索程序，由官方 glob／grep 工具调用；固定位置与 Full 路径规则在 Android 构建补丁中适配 |
| PTY | 系统伪终端输入输出接口，由内置 node-pty 创建以支持用户手动终端；模型 bash 使用自己的执行入口 |
| 图片附件 | 用户通过聊天选择器上传、由上游保存与处理的图片；不等于模型的 `read_image` 工具已经开放，也不证明所选服务商支持看图 |

工具调用顺序：上游工具目录仅输出当前已开放操作 → 收到调用时再次检查固定名单 → 向宿主查询本次实例的合法会话 → 在独立异步上下文内执行文件／搜索或前台命令 → 返回上游结果。Full 可访问应用已有系统权限允许的路径，不获取 root；拒绝后台命令和 `sandbox_permissions` 参数。

模型工具名单以外的调用仍在最终入口拒绝。原版手动终端和插件管理页使用各自的用户操作路径，因此无需开放 `terminal_*` 等模型工具。当前强制使用工具名称与参数的直接调用；PTC 是上游让模型生成程序来组合工具的调用方式，依赖未开放执行器，Android 未启用。

Node 为当前实例维护认证查询连接，宿主登记父子会话；当前上限是 64 个活跃会话、256 个会话归属记录。结束会话移除相关活跃记录，重启清空当前记录，新会话重新登记并统一 Full。连接失效会拒绝后续工具调用并请求停止引擎；该连接不切换权限、不安装插件；手机工具在同一连接上执行，通过独立工作线程保持会话查询和取消可用。手机开关关闭、系统服务断开、会话结束或实例失效会撤销未完成请求，已派发动作须按回执重新观察。

附件选择由 `MainActivity` 处理，只交回当前页面、当前引擎且具有读取授权的内容引用；取消、旧实例或不可读文件不生成附件。图片使用锁定的 sharp WebAssembly 处理，附件与工作文件各自保存。已存在的旧只读模式测试不构成当前默认 Full 的附件或凭据拒读承诺。

插件完整流程见 PLUGINS（本地文档），文件／命令及手机模型工具的逐项判定见 本地能力核对记录（仅本地保留）。

## 构建

需要 JDK 17、Android SDK 36、NDK 28.2.13676358、Python 3.11+、Node/npm、curl、dpkg-deb、readelf 与 `/usr/include/node/node_api.h`。可通过 `ANDROID_NDK_HOME` 指定 NDK。

```bash
python3 tools/voice.py prepare
python3 tools/core.py build --abi arm64-v8a
JAVA_HOME=/usr/lib/jvm/java-17-openjdk ./gradlew :app:assembleDebug
JAVA_HOME=/usr/lib/jvm/java-17-openjdk ./gradlew :app:testDebugUnitTest \
  --tests 'local.dshx.app.CoreTest.normalStartupReusesTheInstallReceiptWithoutScanningTheInventory' \
  --tests 'local.dshx.app.CoreTest.defaultFullBelongsToLiveSessionsAndDoesNotStopWhenARootEnds'
```

模拟器将架构改为 `x86_64`。资源按架构生成，每个 APK 只包含所选架构。构建产物和运行环境缓存不提交 Git。当前主构建输出为 `app/build/outputs/apk/debug/app-debug.apk`；本次另保留两种架构的独立开发包到根目录 `build/outputs/`。

本机 Java 下载连接出现 TLS/网络问题，因此本次验证通过临时的本机 Maven 镜像读取已有缓存并从官方 Maven/Google 源补齐依赖，使用 SDK 36 的 aapt2 资源编译器。该临时镜像不是运行时依赖，也没有写进项目仓库配置。Gradle 固定 9.3.1、Android 构建插件 8.13.2、Kotlin 2.3.20。

| 名称 | 它是什么、由谁创建、负责什么 |
|---|---|

| 会话附件引用 | 官方服务在用户消息中保存的结构化记录，包含附件身份、名称、长度等；不是模型生成的一段路径文本。Android 从当前智能体的可见会话记录取得这些引用 |
| WebAssembly（WASM） | 可由 Node 执行的可移植二进制格式；构建脚本固定并内置 sharp 官方 0.35.5 WASM 包，供原有图片流程调用，区别于把 Linux 原生扩展直接复制到 Android |
| 应用目录同步边界 | Android 创建的应用私有目录，由 Kotlin 宿主通过 `DSHX_DATA_ROOT` 传给运行环境；附件服务同步该目录以内的新目录项，不再尝试打开应用无权访问的 `/data/user/0` |

文件流程为：原版 File 入口 → Android 选择器 → 宿主核对返回地址与读取许可 → 原版附件上传 → 官方服务保存不可变副本和摘要 → 用户发送消息 → 模型收到附件路径描述 → read 根据当前会话的结构化引用取得只读准入 → 完整摘要校验后沿用官方文件工具读取。没有对应引用的其他会话附件、上传后尚未发送的草稿对象和配置目录均不能因此读取。write/edit 和搜索仍限于工作区，网页 Full 不会扩大范围。会话压缩后不再可见的引用也不继续授予读取。

选择器只返回可读取的 `content://` 地址，拒绝应用自身的内容提供者、文件路径和混入无效项的选择结果。内容提供者是 Android 应用注册的文件访问接口；它把一个内容地址映射到实际数据，区别于直接暴露文件系统路径。取消会完成网页回调；旧引擎或旧网页的选择结果不能交给新实例。继续保持 WebView 的 `allowFileAccess=false`、`allowContentAccess=false`；实际选择的文件已成功上传，没有为此放宽目录访问。

图片沿用官方验证、8bit sRGB 规范化、持久副本、请求尺寸转换与缓存流程。sRGB 是常见的标准颜色空间，由图片处理流程统一输出；它与图片分辨率、压缩格式分别描述不同属性。原有 sharp 自动加载官方 WASM 包，没有另写占位图片处理接口。WASM 的第三方许可说明额外保留在运行包 `share/licenses/sharp-wasm32/README.md`；正式分发许可证审核仍未完成。

Android 禁止创建部分硬链接，兼容层沿用复制、独占发布的替代流程；硬链接是让两个文件名引用同一份文件内容的文件系统能力，区别于指向另一条路径的符号链接。复制只读附件后用只读句柄同步，避免因申请写权限而失败；副本仍保持只读，已有目标仍拒绝覆盖。

旋转、尺寸、键盘和系统主题等配置变化保留同一 WebView，由 Compose 按新尺寸布局。选择器打开期间旋转后返回，网页实例和中文草稿保持；正式发送的附件由官方会话保存。未发送的草稿仍是原版网页的内存状态，不承诺在进程结束、安装更新或网页重新加载后恢复。

`chat.css` 是随 APK 打包的网页样式规则，由 MainActivity 在当前本机同源网页完成加载后加入；它只调整现有页面布局，不创建另一套编辑器，也不改变附件和消息接口。规则使用官方页面的 `data-slot`、`data-composer-*` 等语义标记，这些标记由上游组件提供，用来说明区域职责；它们区别于打包工具生成、可能随构建变化的 CSS 类名。更新上游版本时仍需复查这些标记和实际布局。

输入时先由 DshScreen 观察 Android 窗口可见区域，在键盘打开的聊天页隐藏原生底部导航。横屏网页可用高度不超过 240 像素时，样式暂时收起会话标题和输入区统计栏；不超过 160 像素时，再把正文与原有附件入口、权限、模型和发送按钮放在同一行，待发送附件仍占上方完整一行。多行正文在最多 42 像素高的输入区域内滚动。原有操作行使用的尺寸隔离会令网格误判其宽度为零，因此仅在这项紧凑布局中取消该隔离，让网格按按钮的真实宽度分配空间。键盘收起、网页高度恢复后，这些条件规则自动退出，恢复原版标题、统计和输入布局。

| 恢复标记 | 应用私有目录的 `.trust-pending` 文件，由原生组件创建并同步保存；只有完成进程核实、运行包检查和配置重建后清除。原生内存还会锁存恢复要求；磁盘标记被删除也不能取消恢复，每次新的宿主进程首次启动均保守检查并重建配置，区别于会话的内存权限 |
| 恢复备份 | 应用 `files/recovery/` 下的独立目录，保存旧 profile（决定加载哪些插件的启动配置）、Shell 初始化文件和父目录 Node 包加载配置；备份不会自动重新执行 |

启用流程：用户选择当前根会话 → Miuix 原生确认说明范围、停止影响和恢复成本 → Engine 停止所有旧模型任务和命令进程 → 新引擎实例仅为选中会话登记 Full → 持久记录恢复要求 → 官方聊天按原生模式展示工具并在实际执行时再次查询。网页权限可以进一步收紧；网页、模型和 URL 都不能授予原生 Full。Android 强制禁用 bash 的后台选项及超时自动转后台，其他未适配工具仍拒绝。文件工具即使在 Full 中也保留原有工作区边界，任意代码自身可访问全部应用数据。

退出流程：用户改回只读或工作区可写、Full 根会话结束、停止服务或连接失效 → 撤销旧实例权限 → 停止并核实本应用身份的其他进程 → 从 APK 清单校验／修复运行环境 → 通过固定恢复脚本备份并重建启动配置 → 保留会话、附件、工作文件、凭据和模型设置 → 清除恢复标记。显式切换模式会在恢复后重新启动；普通停止则保持停止。App 进程中断后，下次用户启动先执行恢复，不恢复旧 Full 授权或模型任务。任一步失败保持“需要恢复”，不能显示为默认可信。

手动终端的模型授权仍独立：创建官方 PTY（让交互式终端获得输入、输出和尺寸变化的系统接口）前先记录恢复要求，允许用户手动操作，但不授予模型 bash。正常停止或下次启动执行同一恢复流程。

恢复不还原用户工作文件，也不保证清除同一应用身份下恶意代码对全部状态的篡改；本轮实现的是已适配启动环境和正常进程的恢复，不是强隔离。模型凭据与会话按原样保留，不将未知插件配置重新激活。

## 尚未完成（2026-10-22 当前状态）

V1-A/B 源码与入口已逐项核对，但实际运行证据和 V1-C 配套仍未全部完成。插件测试由独立会话执行，不能从源码存在或此前 APK 通过推断本次插件已经在手机通过。当前模型开放 read/write/edit/glob/grep、前台 bash 和十项 phone_* 手机工具，其他工具明确未适配；默认 Full 没有会话开关，也不进行普通启动全目录校验。

## 2026-10-23 语音与本地小模型增量

原生端已接入声音唤醒、句末检测、SenseVoice 本地输入、草稿编辑、正式会话语音对话和按需 Qwen3 小模型。系统没有离线中文声音时可主动下载约 58 MiB 的 MeloTTS 中英播报资源；开始对话前先检查播报条件，普通语音输入可独立使用。下载使用固定版本和 SHA-256 校验，用户显式选择官方或镜像来源，录音不因下载来源切换而上传。

构建前执行 `python3 tools/voice.py prepare`；下载环境需要代理时给该命令传 `--proxy`，不修改设备或系统全局代理。脚本准备固定 AAR、唤醒资源和 llama.cpp 源码；ASR、播报与小模型权重由用户在设置下载，不打进 APK。`VoiceControl` 是 Application 持有的流程对象；`VoiceService` 负责麦克风前台通知；`VoiceInput` 管理单一录音和识别；`VoiceOutput` 负责离线合成与播放；`LocalModel` 调用 C++ CPU 推理。完整术语、调用流程、来源、设备结果和限制见 本地语音实施记录（仅本地保留），第三方声明见 `app/src/main/assets/voice/NOTICE.txt`。

本轮只执行受影响原生包与 Node 语音／用量的定向测试，旧轮次数字不移用。未完成 ARM 真机唤醒、耗电、长时锁屏和回声打断验收；实验播报中唤醒默认关闭，不能把接口存在当作声学质量通过。最终状态与产物由 VOICE 记录。
