# DSHX Android 宿主开发包

> 2026-10-21 最新行为以 本地交付记录（仅本地保留） 和 ADR-019（本地文档） 为准：默认完全权限，取消原生逐会话授权与网页权限切换；普通重新打开或停止再启动复用安装环境，不扫描全目录，不因正常命令重建配置。下面按轮次保留的权限与恢复验证属于历史行为，不代表当前产品要求。最新增量产物位于 `build/outputs/v1-default-full/`，真实模型和前轮 ARM 证据位于 `build/outputs/v1-fixes/`。


当前正式模块是 `app/`。它内置并运行官方 dsh 0.2.1-rc.2 和 Android Node.js 24.18.0-1；管理界面使用 Miuix 0.8.8，聊天继续使用原版 dsh 网页。此包已推进到 V1-B，工作区文件工具、搜索和手动终端已在模拟器验证；原生 Full 与恢复已实现并完成定向检查，完整用户流程尚未验收，其他工具适配与发布验收尚未完成。当前交付范围、安装包和剩余工作见 本地交付记录（仅本地保留）。

## 当前实现与职责

| 名称 | 它是什么、由谁创建、负责什么 |
|---|---|
| `DshApp` | Android 创建的应用对象，持有一份共享的 `Engine`；页面重建不会重新创建引擎 |
| `Engine` | 应用创建的引擎管理对象，后台检查、安装并启动 Node，处理取消、停止、状态和脱敏日志；它不负责绘制页面 |
| `EngineService` | Android 前台服务，由用户的启动动作触发，用通知维持后台运行并提供停止入口；它管理生命周期，耗时工作仍由 Engine 的后台线程执行 |
| `CoreStore` | Engine 创建的离线安装器，校验压缩包和完整文件、目录清单，把完整运行环境放入独立版本目录；会话和工作文件放在该目录之外 |
| `MainActivity` | Android 创建的页面入口，订阅真实状态，用 WebView 承载聊天；WebView 是系统提供的网页组件，不是第二个 dsh 引擎 |
| `DshScreen` | 应用的 Compose 页面，使用 Miuix 卡片、按钮、列表与导航；工作台、聊天、设置和按需诊断均来自实际状态 |
| `ToolPolicy` | Engine 创建的 Kotlin 内存权限表，保存本次运行中每个会话的模式和归属；权限由原生页面改变，不能由网页或模型修改 |
| `PolicyBridge` | Engine 创建的本机查询连接，使用随机端口、实例标识和凭证认证 Node；只接受登记、查询、结束会话和记录任意代码使用；最后一项只能增加恢复要求，不能授权或清除恢复状态，区别于可以修改权限的原生接口 |
| `host.mjs` | 随运行环境打包的 Node 连接客户端，负责认证、登记会话、查询权限及连接失效后的拒绝；缓存只用于工具目录，最终执行会重新查询 |
| `dshx-run` | 构建时编译的小型启动程序，先绑定宿主进程死亡信号，再执行 Node；当前只保证直接引擎进程随宿主结束，未宣称任意后代进程树隔离 |

启动顺序：页面请求前台服务 → Engine 在后台解析完整清单并校验已有安装 → 必要时离线安装 → 创建用户目录与 Android 配置补丁 → 启动受宿主生命周期约束的 Node → 从官方启动行读取本机认证地址 → 页面进入原版聊天。进程结束先完成清理，再发布可重试状态并结束服务，避免旧任务的收尾取消新启动。

停止在安装、已有文件校验和运行阶段均可请求。空闲停止是幂等操作，不会锁死后续启动。运行阶段先请求正常结束，超时再强制结束；取消不会删除用户会话。

## 界面设计

- **工作台**：真实状态、一项主操作、活动时才显示停止/取消。模型与会话入口和诊断分组展示，版本与网页组件信息置后。
- **聊天**：保留原版网页；未启动、网页组件版本不足、连接错误或网页进程异常退出有明确说明。WebView 使用填满父容器的尺寸，修复上游百分比高度布局在默认内容尺寸下变成零高的空白问题。
- **设置**：管理界面的跟随系统、浅色与深色以单选形式设置并持久保存；聊天页自己的外观在 dsh 内设置。工具与权限提供真实活跃会话的只读、工作区可写单选，设置立即更新本次运行的 Kotlin 权限表。
- **诊断**：按需查看最近 120 行，每行有长度上限，可选择文本。隐藏启动 token、常见 API key 和认证头；脱敏不构成识别一切敏感内容的承诺。

Qoder 仅提供暖中性色、低对比边框和克制强调的视觉参考；组件与移动交互来自 Miuix 0.8.8。导航采用 Lucide 同一套细线图标。原生控件保持至少 48dp 的触控高度，页面可以滚动，切换页面不会沿用另一页的滚动位置。

## 运行环境与数据

构建脚本固定 npm 依赖锁、Termux 包版本与 SHA-256，执行 `npm ci --ignore-scripts`，打包官方 JavaScript、网页资源、必要 Android 动态库与许可证。N-API 是 Node 为 C 扩展提供的稳定接口，本项目用极小适配层实现真实内核文件锁和原子独占发布，并从锁定的官方 node-pty 1.2.0-beta.15 源码编译 Android 终端模块。内置 bash 5.3.20 和 ripgrep 15.2.0，以及终端描述、字符编码和搜索所需的动态库。所有打包 ELF 原生文件检查 16KB 对齐；对齐检查不能代替真实 16KB 页设备运行验收。

安装流程先校验压缩包，再逐文件校验路径、长度与哈希。再次启动时核对整个版本目录：除清单登记内容和校验标记以外，额外文件、额外目录、符号链接或非普通文件都会使校验失败；登记为可执行的文件还须具有执行权限。符号链接是指向另一条路径的目录项，由文件系统保存；它与普通文件不同，打开它可能访问目录以外的内容。清理损坏版本、暂存目录与暂存归档时不沿链接访问目标，删除的是链接本身。运行环境根目录本身是链接时拒绝安装。

临时目录只有在全部成功后才激活；取消和失败清理暂存。最终目录包含产物哈希，因此同一上游版本的新构建不覆盖此前构建。当前保留旧目录，不提供自动空间回收或一键回退界面。这些检查负责运行包修复；任意代码执行后的进程核实与配置重建由下文 Full 恢复组件另行负责，完整用户流程尚未验收，也不承诺恶意代码影响的完整恢复。

- 运行环境：`files/core/<version>-<archive-hash-prefix>/`
- 用户目录：`files/home/`；dsh 配置、凭据与会话由上游按自己的格式保存在该目录下。
- 工作区：`files/workspace/`
- 临时文件：`cache/engine/`

当前附件运行环境解包约 714 MiB，压缩包约 221–222 MiB；首次安装还需要暂存和安全余量。更新保留旧环境时需要额外空间。卸载应用或清除数据会删除私有目录中的配置和会话。

进程环境由宿主重新构造，不继承开发机密钥、代理和 Node 注入参数。网页服务只监听 `127.0.0.1`，使用随机端口和官方启动认证；只允许同一端口的网页导航。模型请求发送到用户配置的服务商，本地执行不代表离线推理。

## 文件工具与手动终端

| 名称 | 它是什么、由谁配置、负责什么 |
|---|---|
| 工作区 | 宿主在 `files/workspace/` 创建的文件目录；模型文件工具只操作这里，区别于保存凭据、配置和会话的 `files/home/` |
| `policy.mjs` | 随运行环境打包的 Android 固定规则，宿主通过 `DSHX_WORKSPACE` 指定边界；默认准入 read/write/edit/glob/grep，原生 Full 另允许前台 bash，拒绝模型提权与其他工具 |
| `AndroidFiles` | Android 配置补丁注册的文件服务，继承官方文件服务的原子写入、旧版本检测和只读策略；模型读取期间检查真实路径，每次写入再次检查目标 |
| 异步调用上下文 | Node 为一条异步执行链保存独立状态的机制；由工具真实执行入口创建，用来区分模型文件操作和 dsh 自身配置读取，避免使用会影响并发任务的全局开关 |
| ripgrep（rg） | 内置的文件搜索程序，由官方搜索插件启动；负责 glob 与 grep 的实际匹配，Android 补丁固定其二进制位置并检查搜索根目录 |
| PTY | 操作系统提供的伪终端输入输出接口，由官方 node-pty 模块创建；让网页终端像普通终端一样输入、调整行列和结束 bash，区别于模型的 bash 工具 |

发送模型请求前，官方工具服务的三类目录输出均按 Android 准入规则和原生会话模式过滤：默认提供 read/write/edit/glob/grep，只读仅提供 read/glob/grep，原生 Full 另提供前台 bash。目录描述每个工具的名称和参数，帮助模型选择可调用的操作；过滤目录与执行时检查承担不同职责，两者同时保留。历史会话仍保留已知工具名称和定义，避免旧记录无法解释。

Android 暂使用直接工具调用格式：模型返回工具名称与参数，由 dsh 执行。上游另有 PTC（Programmatic Tool Calling，程序式工具调用），把多个操作放入模型生成的程序后运行；这依赖当前未开放的代码执行工具，因此 Android 不使用这一格式，已有 PTC 配置也回到直接调用。

模型工具执行顺序：官方工具入口先检查 Android 固定准入 → 文件工具向 Kotlin 查询本次实例的会话权限 → 获准工具进入独立异步上下文 → 文件服务将路径转换为真实物理路径并核对宿主工作区 → 沿用官方读写、旧版本检测或搜索实现 → 官方入口返回结果。即使模型返回目录中没有的工具，执行入口也会拒绝。子智能体同样经过此入口；普通插件的放行监听器不能移除固定规则。

原生会话权限补充：每次启动生成新的实例标识，即代表一次引擎运行的随机编号；Node 用本次凭证建立持续查询连接。官方智能体登记时，适配器从上游活跃智能体记录查明由哪个父智能体创建，再登记对应会话。这里使用当前运行关系，不使用旧会话文件中的分支历史，因此独立恢复的历史分支可以作为独立根会话，实时创建的子会话则继承根会话模式。根会话是这组实时对话的权限归属；原生页面只为根会话设置模式。

只读模式提供 read/glob/grep，工作区可写另提供 write/edit；当前会话附件始终只读。每次模型请求前刷新权限快照，三类模型工具目录按会话过滤；每次文件工具执行前重新查询 Kotlin，文件服务的写入入口再检查当前调用是否只读。网页选择更宽权限不能扩大原生授权。切换模式不会撤回已经发生的修改，已开始的操作可能仍完成；后续调用按新模式检查。

当前实例最多保存 64 个活跃会话、256 个会话归属记录。结束会话会移除活跃记录，但保留原归属和根模式，防止以同一会话标识换父会话绕过只读；结束后按原归属恢复仍保留设置。停止或重启引擎清除本次权限，重新启动后回到默认工作区可写。合法查询连接失联会立即关闭原连接入口、清空权限并请求停止引擎，恢复需要新实例；无效查询仅拒绝该请求，陌生或重复认证连接不撤销合法连接。未认证连接最多四条、每条握手总时间三秒、请求长度受限。此连接是受信 Node 的宿主查询机制，不能隔离持有同一应用身份的任意恶意代码。

dsh 在发送消息前会向父目录查找项目标记并读取自身配置。此前把所有文件读取都限制在工作区，导致查找父目录 `.git` 时整个消息失败；现在只对实际模型文件读取施加固定边界，宿主上下文准备保留官方行为。每次写入仍检查边界。并发回归验证模型读取被拒绝的同时，宿主可以读取自己的外部配置。固定边界属于受信文件工具的路径约束，不是对恶意任意代码的内核隔离；同一应用身份下并发替换目录的底层竞态仍有上游接受的限制。

网页的 Full access（上游最高权限选项）不能扩大原生授权或自行启用模型命令执行。最新包已实现原生 Full 实例授权，相关定向检查及说明页检查通过；启用后返回选中会话、真实命令及退出恢复的完整流程尚未验收，详见下文增量。用户可自行从原版网页创建手动终端，它是明确的手动操作入口，不会因此授权模型的 bash 工具。应用停止时终端一并清理；这不代表任意恶意后代进程的完整隔离保证。

Android 启动补丁先禁用上游 `fs-sandbox`，再插入 `AndroidFiles`；已有行的 `name` 在官方补丁格式中是名称断言，不能用来替换插件。测试直接组合官方基础、网页与 Android 三层补丁，验证原服务禁用、新服务注册且无跳过警告。

## 构建

需要 JDK 17、Android SDK 36、NDK 28.2.13676358、Python 3.11+、Node/npm、curl、dpkg-deb、readelf 与 `/usr/include/node/node_api.h`。可通过 `ANDROID_NDK_HOME` 指定 NDK。

```bash
python3 tools/core.py build --abi arm64-v8a
JAVA_HOME=/usr/lib/jvm/java-17-openjdk ./gradlew :app:assembleDebug
JAVA_HOME=/usr/lib/jvm/java-17-openjdk ./gradlew :app:testDebugUnitTest :app:lintDebug
```

模拟器将架构改为 `x86_64`。资源按架构生成，每个 APK 只包含所选架构。构建产物和运行环境缓存不提交 Git。当前主构建输出为 `app/build/outputs/apk/debug/app-debug.apk`；本次另保留两种架构的独立开发包到根目录 `build/outputs/`。

本机 Java 下载连接出现 TLS/网络问题，因此本次验证通过临时的本机 Maven 镜像读取已有缓存并从官方 Maven/Google 源补齐依赖，使用 SDK 36 的 aapt2 资源编译器。该临时镜像不是运行时依赖，也没有写进项目仓库配置。Gradle 固定 9.3.1、Android 构建插件 8.13.2、Kotlin 2.3.20。

| 名称 | 它是什么、由谁创建、负责什么 |
|---|---|
| 系统文件选择器 | Android 提供的文件选择页面；用户点击原版聊天的 File 入口后，由 MainActivity 打开。它返回用户选中的内容地址及临时读取许可，区别于授予应用整个存储目录的权限 |

| 会话附件引用 | 官方服务在用户消息中保存的结构化记录，包含附件身份、名称、长度等；不是模型生成的一段路径文本。Android 从当前智能体的可见会话记录取得这些引用 |
| WebAssembly（WASM） | 可由 Node 执行的可移植二进制格式；构建脚本固定并内置 sharp 官方 0.35.5 WASM 包，供原有图片流程调用，区别于把 Linux 原生扩展直接复制到 Android |
| 应用目录同步边界 | Android 创建的应用私有目录，由 Kotlin 宿主通过 `DSHX_DATA_ROOT` 传给运行环境；附件服务同步该目录以内的新目录项，不再尝试打开应用无权访问的 `/data/user/0` |

文件流程为：原版 File 入口 → Android 选择器 → 宿主核对返回地址与读取许可 → 原版附件上传 → 官方服务保存不可变副本和摘要 → 用户发送消息 → 模型收到附件路径描述 → read 根据当前会话的结构化引用取得只读准入 → 完整摘要校验后沿用官方文件工具读取。没有对应引用的其他会话附件、上传后尚未发送的草稿对象和配置目录均不能因此读取。write/edit 和搜索仍限于工作区，网页 Full 不会扩大范围。会话压缩后不再可见的引用也不继续授予读取。

选择器只返回可读取的 `content://` 地址，拒绝应用自身的内容提供者、文件路径和混入无效项的选择结果。内容提供者是 Android 应用注册的文件访问接口；它把一个内容地址映射到实际数据，区别于直接暴露文件系统路径。取消会完成网页回调；旧引擎或旧网页的选择结果不能交给新实例。继续保持 WebView 的 `allowFileAccess=false`、`allowContentAccess=false`；实际选择的文件已成功上传，没有为此放宽目录访问。

图片沿用官方验证、8bit sRGB 规范化、持久副本、请求尺寸转换与缓存流程。sRGB 是常见的标准颜色空间，由图片处理流程统一输出；它与图片分辨率、压缩格式分别描述不同属性。原有 sharp 自动加载官方 WASM 包，没有另写占位图片处理接口。WASM 的第三方许可说明额外保留在运行包 `share/licenses/sharp-wasm32/README.md`；正式分发许可证审核仍未完成。

Android 禁止创建部分硬链接，兼容层沿用复制、独占发布的替代流程；硬链接是让两个文件名引用同一份文件内容的文件系统能力，区别于指向另一条路径的符号链接。复制只读附件后用只读句柄同步，避免因申请写权限而失败；副本仍保持只读，已有目标仍拒绝覆盖。

旋转、尺寸、键盘和系统主题等配置变化保留同一 WebView，由 Compose 按新尺寸布局。选择器打开期间旋转后返回，网页实例和中文草稿保持；正式发送的附件由官方会话保存。未发送的草稿仍是原版网页的内存状态，不承诺在进程结束、安装更新或网页重新加载后恢复。

`chat.css` 是随 APK 打包的网页样式规则，由 MainActivity 在当前本机同源网页完成加载后加入；它只调整现有页面布局，不创建另一套编辑器，也不改变附件和消息接口。规则使用官方页面的 `data-slot`、`data-composer-*` 等语义标记，这些标记由上游组件提供，用来说明区域职责；它们区别于打包工具生成、可能随构建变化的 CSS 类名。更新上游版本时仍需复查这些标记和实际布局。

输入时先由 DshScreen 观察 Android 窗口可见区域，在键盘打开的聊天页隐藏原生底部导航。横屏网页可用高度不超过 240 像素时，样式暂时收起会话标题和输入区统计栏；不超过 160 像素时，再把正文与原有附件入口、权限、模型和发送按钮放在同一行，待发送附件仍占上方完整一行。多行正文在最多 42 像素高的输入区域内滚动。原有操作行使用的尺寸隔离会令网格误判其宽度为零，因此仅在这项紧凑布局中取消该隔离，让网格按按钮的真实宽度分配空间。键盘收起、网页高度恢复后，这些条件规则自动退出，恢复原版标题、统计和输入布局。

| 名称 | 它是什么、由谁创建、负责什么 |
|---|---|
| Full | 用户在 Miuix 原生设置中确认的完全信任模式，允许选定会话及其子会话执行已适配的前台 bash 命令；区别于网页中的同名权限，原生授权是额外的上限 |
| `EngineRecovery` | Engine 创建的恢复组件，在任意代码获准运行前同步保存恢复标记，并检查 `/proc` 中本应用身份的其他进程；它不负责修改会话数据，也不提供恶意代码隔离 |
| `recover.mjs` | 随 APK 校验的独立恢复脚本，由 Engine 在停止命令进程、校验运行环境后使用可信 Node 执行；它只保留官方模型服务商与默认模型的配置数据，备份其他启动配置并重建内置 web 配置 |
| 恢复标记 | 应用私有目录的 `.trust-pending` 文件，由原生组件创建并同步保存；只有完成进程核实、运行包检查和配置重建后清除。原生内存还会锁存恢复要求；磁盘标记被删除也不能取消恢复，每次新的宿主进程首次启动均保守检查并重建配置，区别于会话的内存权限 |
| 恢复备份 | 应用 `files/recovery/` 下的独立目录，保存旧 profile（决定加载哪些插件的启动配置）、Shell 初始化文件和父目录 Node 包加载配置；备份不会自动重新执行 |

启用流程：用户选择当前根会话 → Miuix 原生确认说明范围、停止影响和恢复成本 → Engine 停止所有旧模型任务和命令进程 → 新引擎实例仅为选中会话登记 Full → 持久记录恢复要求 → 官方聊天按原生模式展示工具并在实际执行时再次查询。网页权限可以进一步收紧；网页、模型和 URL 都不能授予原生 Full。Android 强制禁用 bash 的后台选项及超时自动转后台，其他未适配工具仍拒绝。文件工具即使在 Full 中也保留原有工作区边界，任意代码自身可访问全部应用数据。

退出流程：用户改回只读或工作区可写、Full 根会话结束、停止服务或连接失效 → 撤销旧实例权限 → 停止并核实本应用身份的其他进程 → 从 APK 清单校验／修复运行环境 → 通过固定恢复脚本备份并重建启动配置 → 保留会话、附件、工作文件、凭据和模型设置 → 清除恢复标记。显式切换模式会在恢复后重新启动；普通停止则保持停止。App 进程中断后，下次用户启动先执行恢复，不恢复旧 Full 授权或模型任务。任一步失败保持“需要恢复”，不能显示为默认可信。

手动终端的模型授权仍独立：创建官方 PTY（让交互式终端获得输入、输出和尺寸变化的系统接口）前先记录恢复要求，允许用户手动操作，但不授予模型 bash。正常停止或下次启动执行同一恢复流程。

恢复不还原用户工作文件，也不保证清除同一应用身份下恶意代码对全部状态的篡改；本轮实现的是已适配启动环境和正常进程的恢复，不是强隔离。模型凭据与会话按原样保留，不将未知插件配置重新激活。

## 尚未完成

默认只开放 read/write/edit/glob/grep；原生只读会话仅有 read/glob/grep；原生 Full 另允许前台 bash，其他工具继续在最终执行入口拒绝。原版网页中的插件入口及历史工具记录仍可能出现，不能据此认为 Android 已支持对应能力。

其他模型工具、插件安装管理、任意开发者插件和后续 Android 手机能力尚未完成；实体 ARM 设备、最低系统、真实 16KB 页、真实模型服务、后台限制、更多输入法及附件来源、发行签名和分发许可证仍需 V1-C。当前不是全 v1 发布版，不承诺恶意代码之间的文件或网络隔离。

启动时完整校验约 45,000 个文件仍有明显等待，尚未完成启动体验优化；当前保持完整校验与明确等待状态，不以减少重复测试为理由跳过校验。
